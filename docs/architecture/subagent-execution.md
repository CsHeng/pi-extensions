# Managed Subagent Execution

`csheng_subagent_sessions`, registered by `extensions/subagents/index.ts`, is the runtime managed transport. Historical one-shot `csheng_subagents` remains evaluator and architecture reading in [Subagents](subagents.md), not a registered tool. Pi owns each native agent loop and session append. The parent owns decomposition, permissions, review adjudication, repair instructions, candidate application, and acceptance. The extension does not infer or advance that semantic workflow.

## Requests and authority

| Action | Contract |
| --- | --- |
| `create` | `requestId` and one to ten tasks; captures and pins immutable Git input before admission. TUI/RPC default to an accepted submission receipt, not a completed report. |
| `continue` | `episodes` with handle, requestId, expectedEpisode and message. Reuses the same role, fixed input, worktree and native history; write hints are advisory. |
| `inspect` | Optional handle or runId; reads bounded state without a model. Run views preserve their original episodes even after an early task is repaired. |
| `join` | runId; waits for its terminal result. Cancelling this wait does not cancel execution. |
| `cancel` | runId and optional taskId; explicit execution cancellation. Task cancellation during candidate freeze returns too-late. |
| `refresh` | Handle and expectedEpisode; explicitly integrates new parent input into an idle worktree without discarding pending edits. Conflicts preserve both versions. |
| `apply` | Handle, expectedEpisode and candidateId; explicitly integrates a frozen Git candidate into the parent worktree, not the index. Does not refresh task input or accept work. |
| `close` | Handle, expectedEpisode and optional retain/discard disposition. Discard removes exact-owned Git worktree/refs and runtime artifacts while retaining registry/native evidence. |

Print/JSON one-shot hosts default to foreground execution; interactive/RPC calls may also request `mode: "foreground"`. Expensive checkout and dependency preparation follows admission. Capacity and explicit locks are session-scoped across submissions, while the existing graph scheduler retains predecessor ordering. No polling, automatic apply, retry, recovery, or semantic acceptance is added.

Input is action-specific and closed: arbitrary paths cannot replace handles, and duplicate handles, unknown fields, invalid versions, or oversized input are rejected. The provider-compatible flat schema documents each action's required fields; missing-field failures retain the valid requested action and name the missing fields. An unrecognized action is null in result schema v3, rendered as a failed request rather than a fabricated inspect. Repository trust and owner/branch checks precede access. Fresh episodes recheck repository admission, routes, hard execution bounds, and capabilities. No task can change its persistent route defaults or grant itself another role or external write root.

Managed workers require explicit repository-wide input `scope: ["."]`. Explorer and reviewer remain read-only. All roles may receive explicit bounded external read grants for Git or non-Git regular files and directories; worker external writes remain forbidden. The parent may explicitly grant a reviewer a candidate's private Git-contained source or exact files when it needs pre-apply review; the extension does not automatically project one child's state into another or treat a review report as an apply decision.

Independent runs may overlap under shared global/role capacity. Mutation of each task remains serialized; parent apply has a separate shared gate. Known in-process root registry writers queue; foreign or unknown disk locks still fail closed. Hard predecessor edges are for approved execution order only, never an intervening parent decision. Edges pass reports, not candidate files. File-dependent successors require explicit parent apply between dispatches. Overlapping write hints do not serialize isolated worktrees; explicit resource locks still protect shared external resources.

## Trusted host tools, not an OS sandbox

A managed worker has Pi-compatible `read`, `grep`, `find`, `ls`, `edit`, `write`, and `bash`, including native schemas and image reads. Its tools share one private source directory and a worker-local FIFO. Bash, source edits, local tests, and repair can therefore observe the same bytes. Existing tools and dependencies are used; the extension does not provision containers, packages, binaries, credentials, or network services.

This is trusted host execution. File-tool guards, private directories, filtered Git defaults, inventories, and candidate checks are not OS restrictions on bash. They do not isolate host credentials, network, filesystem access, or hostile process escape. Optional `writePaths` predict initial regions, not exact-file export authority. Native writes remain contained in the owned source root and exclude Git metadata/dependency roots; actual Git changes are validated at candidate freeze. Parent instructions and applicable external controls remain necessary for host-side authority.

Bash uses an ordinary POSIX process group, waits for operation cleanup, and terminates its known descendants on cancellation, timeout, or exit. Managed native search processes are also drained on shutdown. Unconfirmed writer cleanup latches failure; a candidate cannot be frozen merely because an assistant said it finished. This is normal process cleanup, not an adversarial containment guarantee. The mandatory native `csheng-worker-lifecycle` ready/stopped pair is separate from optional performance markers.

## Read-only Git evidence

Explorer and reviewer add child-only `git_read` to `read`, `grep`, `find`, and `ls`, without bash/edit/write. The request chooses `status`, `diff` (`commits`, `index`, or `worktree`), single-file historical `show`, or bounded `log`; it supplies an authorized repository selector and literal owner-relative paths. Commit/ref inputs resolve to exact commit IDs, and `show` returns a blob ID. No arbitrary argv, shell, checkout, apply, fetch, configuration mutation, or additional read grant is exposed. Worker tools and owned-worktree write confinement are unchanged.

Git metadata admission permits ordinary repositories and registered linked worktrees, rejects unsupported layouts, external/symlinked object stores, alternates, grafts, config includes, filters, partial clones and worktree-specific configuration, and ignores replacement objects throughout Git phases. Parent symlink traversal is refused; historical symlink blobs are read literally, never followed. External read subdirectories remain narrow grants. External diff/textconv, pagers, hooks, fsmonitor and network protocols are disabled; mutable content-filter/encoding declarations fail closed. These checks are a typed capability boundary in a trusted host, not an adversarial filesystem-race sandbox.

Historical gitlink changes retain short recorded commit deltas without submodule recursion. Mutable queries involving scoped index/HEAD gitlinks are explicitly unsupported rather than inspecting another Git store. Binary or attribute-suppressed patches return incomplete/unsupported evidence. Mutable operations fingerprint scoped source/index/HEAD before and after; detected drift discards output. Equal endpoint fingerprints are not a transactional snapshot or acceptance judgment.

Results have explicit completeness, a 64 KiB UTF-8-safe text limit, bounded paths/inventory/metadata, at most 100 log entries and 2,000 show lines per request; subprocess output is bounded at 1 MiB and each Git process at 30 seconds with cancellation. Git stays in the managed child's process group for owner shutdown. Unavailable or incomplete output must not be represented as a full diff. Delegators supply exact accessible patches/blobs or verified Git query capability, accessible review rules, and current input identity; a continuation alone does not refresh a captured source snapshot.

## Source and dependency state

A fresh independent index captures current visible tracked and non-ignored files, including staged/unstaged/untracked content without changing the parent index. Git trees and internal commits are pinned by exact-owned refs; no user branch commit is created. Each task has a detached linked worktree with its own index and shared Git object database. The `.git` file and administrative identity are validated as linked-worktree metadata, not mistaken for a private repository directory. Managed Git commands suppress inherited Git configuration, hooks and filters; unsupported source types fail visibly. Trusted bash can still access host resources and shared Git metadata: this is not an OS sandbox.

Ignored top-level `node_modules` is an independently copied runtime input, including a reserved absent state. An existing ordinary-source `node_modules` is not silently reclassified. There are no shared writable dependency mounts or hardlinks. Dependency changes are staged and switched only when the parent's dependency digest changes; unchanged parent inputs preserve worker-local dependency edits. Internal source links can be dangling, but dependency links must resolve within the staged logical source/dependency namespace. External/absolute links, special entries, unsafe ancestors, and Git redirects are rejected.

Continue never refreshes input implicitly, including a cancelled queued task that has not yet checked out its pinned input. Explicit refresh performs a Git three-way integration and updates the private dependency input only while idle. Candidate freeze discovers additions, deletions, renames, executable modes, binary changes and contained symlinks relative to that fixed input; private dependency roots are excluded. Command outputs and auxiliary files belong in scratch. Failures retain diagnostic state rather than silently resetting, reinstalling, or recapturing input.

## Registry, native continuity, and replay

Private data lives under `<agent-dir>/subagent-managed-sessions`, separate from both ordinary Pi sessions and one-shot diagnostic retention. New records, batch caches and tool envelopes use version three. Versions one and two are inspect/close-only and retain their original version; continuation, refresh and apply refuse legacy records. There is only one writable source/candidate backend. Recovery reads evidence without replaying executions; interrupted or unknown writers require explicit reconciliation. Downgrade readability is not guaranteed. Each `session_<uuid>` holds a registry, native JSONL, source, scratch, frozen candidate artifacts, and optional episode observations. Batch request records are separate. Directories/files use private permissions; writes use exclusive locks and staged fsync/rename. Unknown lock ownership is not reclaimed automatically.

There are at most ten open logical records per repository/parent session, including records on sibling branches, and at most 256 episodes per record. Close releases open-record slots, not all retained history. Close/discard removes owned source, scratch, candidate, and input-staging artifacts while retaining closed registry/native evidence; it never undoes an already exported prefix. No global storage inventory runs on normal actions or replay. Hard bounds remain 8 GiB per source snapshot or dependency copy, 100,000 entries per workspace inventory, 32 MiB per native session, 100,000 parsed native rows, 2 MiB per registry, and 64 MiB per candidate. These are checked logical limits, not OS disk quotas; required-data I/O and integrity failures still fail visibly.

Normal actions, startup, and replay no longer scan the entire managed root or emit aggregate storage warnings. Historical envelopes can still display their old warning field without mutating records. Per-workspace, registry, native and candidate limits remain enforced. No idle TTL, background scan or automatic storage cleanup exists; a separate estimate/cleanup CLI is not part of this implementation.

Cleanup is user-owned. Close unneeded handles with `disposition: "discard"` to remove working files while preserving registry/native history. A full reset is outside the tool: stop all Pi/subagent processes using the agent directory, then back up and remove `<agent-dir>/subagent-managed-sessions` (default `~/.pi/agent/subagent-managed-sessions`). This abandons retained histories, candidates, replay records and continuation handles for all repositories using that directory; ordinary Pi sessions, applied repository edits and route settings are separate. Never delete individual registry/native files to bypass integrity checks or perform a reset while managed writers are active.

Each episode starts a bounded native Pi print/JSON child with the same native file and source. The session-owned supervisor may outlive its submission tool call, but there is no persistent RPC child, detached mission, automatic resume, or reconstructed prompt history. Pi performs compaction, tree/fork behavior, and native appends. The parent side reads the physical native append range without opening or repairing the session. A changed leaf, copied/forked owner, other repository, unknown request outcome, or interrupted writer does not gain continuation authority.

At acceptance, the role's effective `inheritSkills` boolean is stored on the queued record and used for that episode even if configuration changes before launch; later accepted episodes resolve again. The already-loaded effective parent Skill catalog owns native exclusions and precedence for normal Pi turns. Only selected project Skill paths that belong to the captured Git input are retained privately across continuation, even if a later parent resource reload removes the original files; explicit refresh recaptures that selection. Ignored private project guidance instead follows the current effective parent catalog on each episode and is never treated as snapshot membership. Their paths are remapped to the captured source, and only selected canonical Skill file/directory paths go through CLI. Direct service callers without a parent catalog use Pi's public non-installing Skill parser with project-before-user fallback and cannot infer package-specific enabled resources. Captured repository Skill membership and bytes take precedence over mutable parent source, while ignored private and user-installed guidance is read at its owner. Actual Skill bodies/references remain on-demand reads behind a separate read-only guidance grant pinned to selected physical owners. Native context discovery remains active independently of this switch; original-project ancestors precede the child snapshot's selected repository override, while managed-storage ancestors are omitted. User-installed and trusted private resources outside the captured Git input can change between episodes. No ordinary extensions, MCP servers, parent conversation history, or external read-root project settings are imported. Host-side guidance discovery never provisions a package; the unchanged Pi subprocess still follows its own configured startup package/offline policy. This is a trusted-host guard, not an OS sandbox or shell network policy.

A terminal request replays committed episode evidence without another launch, usage charge, or current route lookup. Each returned v3 transport envelope has fresh bounded request telemetry: parent owner and invocation identity, start/duration, known task widths, actual launches, replayed episodes, and only actually observed extension/configuration epochs. Each episode separately retains its original execution provenance, route, and (for new episodes) the actual `inheritSkills` boolean; old v3 records lacking the optional field remain unknown rather than being backfilled from current configuration. Inspect, parse refusals, and replay do not load configuration solely for attribution; their configuration epoch can be unavailable. Replay metadata describes this invocation, not another execution of the historical episode. Authorization still applies. The cached view is historical, not a fresh filesystem validation; use inspect for current state. Request errors are separate from the prior committed result. An unknown outcome is not automatically replayed. After a child returns, native validation, candidate freeze, and required result save are separate finalization stages: a failure preserves recorded child output, usage, duration, and execution status while making the overall result failed and non-applicable. The final registry commit uses an owned pending marker so a post-rename durability error cannot expose an interim successful worker candidate; uncertain persisted state remains non-actionable across replay. A missing or historically zero duration without execution provenance is unavailable, not a known fast run. Native parser rejection reports a bounded reason category without exposing history contents. Quiet successful non-retrying compaction can retain a valid report, but fresh settlement and closed activity remain required; failed, aborted, or retrying compaction cannot resurrect stale output.

A bounded ephemeral current-owner index exposes handles, episodes, state, and candidate metadata, not reports or private paths. It respects project trust and active tools, neither enables disabled tools nor resumes a task, and native history remains authoritative rather than a copied summary. The index is projected once for a new native user-message occurrence actually prepared in model context, and once per recovery boundary: session start, tree navigation, and successful compaction. Receipts, withdrawn/replaced queue drafts and historical context do not open input windows. Pi 0.86.0 queued or mixed-source occurrences have no authoritative source identity; they may open the same non-authorizing reference window, never claim human intent or permission. Unambiguous ordinary extension controls do not open windows. No receipt-text matching, FIFO or human-first inference is used. Structural message digests confirm native-event participation in the host's cloned context, not final wire content after arbitrary later transformations. The projection remains independent of workflow, and explicit inspect/tool guards remain authoritative. A failed or retried provider request keeps the projection pending so the retry still carries it, and settlement clears it. Normal same-process reload and context rebuilding therefore restore the projection only through those boundaries instead of on every request.

## Candidates and recovery

Unapplied C1 and C2 are both compared against the explicit input base B0. Apply does not change that base. An explicit refresh establishes a new input base for later repair. A complete successful report without actual changes produces no candidate.

Freeze creates immutable Git candidate objects and validates source identity, changed paths, environment and byte limits. Apply uses Git three-way merge against a fresh capture of the current parent worktree. Compatible parent edits and renames are preserved, conflicting content is not overwritten, and the parent index is unchanged. Candidate `changedPaths` remain immutable; `appliedPaths` records the actual parent integration footprint, including renamed destinations or an empty no-op footprint.

Publication is not a multi-file filesystem transaction or automatic rollback. An uncertain failure marks apply unknown, and `applying`, `partial`, or `unknown` blocks continuation until explicitly reconciled. These recovery and native-leaf checks run on the freshly locked task record, not a stale pre-refresh copy. Reapplying an applied candidate returns its historical outcome without writing again; it does not prove current parent bytes.

Close/retain preserves the working state and evidence. Close/discard removes owned source, scratch, candidate, and input-staging artifacts while retaining the closed registry/native history. It never undoes an already exported prefix. Cached reports, process settlement, candidate creation, and apply status are all distinct from parent acceptance.

## Observation and consumers

Public event hooks record client-observed assistant, streamed thinking, local-tool, delegation-wait, and compaction spans. Each interaction uses an opaque process clock and origin. Missing, backward, nonfinite, duplicate, or unclosed endpoints remain incomplete. Final thinking blocks without streamed endpoints do not become complete zero reasoning. Ordinary parent turns, idle shutdown, and inactive delegation tools write no parent observation. Hooks own no timer, UI slot, dispatch, provider payload, or model configuration.

Native v1 observations contain direct assistant/compaction/branch-summary usage, owner/entry identities, configured child tools/context window/capability hash, and scalar command endpoints/status/source/environment hashes. No command text or prompt is copied into these markers. A failed summary without usage is unknown, not free. A structurally valid owned native range can retain usage, commands, and capabilities without a terminal timing marker; missing timing stays unavailable rather than erasing the other planes or inventing zero duration. Partial physical tails, owner/leaf drift, and unreadable ranges still fail closed. Retained usage describes committed recorded rows, not an assurance that a forcibly stopped in-flight provider request has a complete bill. Configured tool evidence is host state, not the final provider payload after later handlers. Usage remains Pi/provider-reported; there is no pricing estimator, server-utilization inference, or provider-quota estimate.

Worker command markers use version-two domain-separated hash keys for nonempty host tool-call IDs bounded to 4 KiB UTF-8. Host IDs are not validated as managed handles. New observation projections declare `commandCorrelationVersion: 2`; legacy raw-ID projections normalize before comparison, while legacy missing IDs remain uncorrelated. Duplicate, unknown-version, or unmatched markers retain partial command coverage. The outer task timeout does not synthesize a command timeout marker.

Optional observation sidecars are bounded to 64 KiB per episode and are not part of the required registry, request, or terminal ACK. No aggregate storage advisory reclaims sidecars. Missing/corrupt caches hydrate as unavailable; an optional write failure cannot invalidate a candidate or committed result. Native history, source integrity, required lifecycle evidence, and candidate failures are never waived as telemetry failures.

The evaluator's `observations` section consumes owned physical parent windows and child projections, deduplicating native owner/entry and logical handle/episode identities. Copied fork prefixes, nested aggregates, replay, inspect, and repeated reads do not create new usage. Prior valid episode evidence survives a missing cache on reread; conflicting stable evidence fails closed. Parent usage and child usage are separate. Cross-run worker union requires matching clocks/origins; child reasoning/tool/compaction summaries sum per-episode measurements as effort, never an unrelated-clock union. Unattributed wall gaps are not asserted user idle.

The legacy evaluator counters remain explicitly historical `csheng_subagents-only` one-shot totals; they do not describe the registered managed tool. Exact-session mode supplies native/managed summaries. The separate `managedDispatch` section reads structured invocation facts even without a settled parent observation window. Its v3 `async` section counts admission receipts separately; persisted owner-tagged `csheng.subagents.execution.v3` terminal events own launches, queue/preparation/workspace/child and submission-to-terminal timing. Task/run events, replay, inspect and join do not duplicate native usage. Conflicting terminal facts fence timing even when a later event adds timing detail. Task and run latency use the same epoch activation filter. Asynchronous worker occupancy is not forced into an unrelated parent interaction window; unavailable cross-turn timing is reported as unavailable. It validates v2 owner/invocation identity, deduplicates equal records, excludes copied owners, and invalidates conflicts. Current-epoch matching requires the invocation's effective revision pair; missing pairs stay unassigned rather than being inferred from a returned old episode, mtime, or current configuration. Historical v1 action/status is recorded-result evidence, not unique owned invocation evidence. Optional explicit `--disposition` JSON declares parent acceptance and bounded entry scope; missing or null endpoints/repair counts stay unknown. Such a declaration neither changes runtime state nor applies to every candidate in a wider report automatically. See the maintainer metric schema for exact fields.

Managed tool content is bounded parseable JSON with every handle, episode, candidate identity, and available submission `kind`/`runId`/`generation` preserved before report truncation. `join(mode: foreground)` normalizes to canonical join; async mode on join is rejected. TUI results distinguish request refusal, stored idle/interrupted/closed state, episode outcome, report completeness, and apply. Model content and both collapsed/expanded TUI include the actual provider/model/thinking when recorded, including failed episodes and replay. Runtime output and the ephemeral index do not emit acceptance pseudo-state; acceptance is parent-owned. Offline `parentAccepted: null` still represents missing explicit disposition evidence. Foreground activity uses Pi's tool-update channel. Async activity uses session observer snapshots instead of invoking the settled submission's progress callback. Terminal facts are persisted before publication and wake; one pending wake is coalesced until the public context hook consumes it. Owner changes, shutdown and abort/error fence automatic wake. The workflow consumer binds evidence to dispatch-time contract/attempt/input, reconciles terminal-before-receipt and later input changes, and never promotes historical inspect/join results to a newer attempt or contract. In TUI mode the core also publishes bounded `csheng.subagents.observer.v2` snapshots at payload version 3, including a truncated assignment headline and current tool names. Default-loaded `subagents-ui` is a read-only `/subagents-ui` and `Ctrl+Alt+F` overlay; keyed footer status, below-editor widget, and custom entries stay off by default. `status-footer` and `work-timing` retain independent TUI contracts. `work-timing` retains its independent v1 parent-only TUI semantics.

## Accounting boundary

Pi can include nested LLM work in footer, `/session`, and RPC totals when a tool returns top-level `usage`. These subagent adapters do not currently supply that field. Their `details.usage` and native/evaluator aggregates are separate evidence, not automatic additions to the parent Pi total; provider-side accounting of child calls still applies. Never add cumulative replay/inspect observations to parent assistant usage or treat missing usage as zero. Native billing forwarding is not implemented.

## Verification and removal

Deterministic tests cover contracts, linked worktrees/dependencies, real local command test/repair, queued cancellation and pinned-input continuation, concurrent refresh/uncertain-apply races, root writer serialization, shared capacity, replay, immutable Git candidate integration, legacy read-only behavior, storage advice and producer/consumer ownership. A real RPC-mode Pi SDK host with synthetic parent provider and native child processes exercises overlapping tasks, independent parent work, event-driven workflow waiting, early apply, explicit refresh, same-native-history repair, late sibling ownership and exact-owned cleanup. It makes no provider calls and grants no semantic acceptance. Disposable synthetic-provider tests exercise both the development Pi API and installed CLI, native append/reopen, same-process reload, compaction, actual tool progress, and cross-episode accounting. They are not evidence of economic benefit or successful real-provider semantic delivery.

Temporary/installed subagent probes discover the managed tool and assert its absence when the extension is disabled, without inference. The separately gated live script is not managed continuation acceptance and is not a verified package co-load proof; parent owns acceptance of that lane. Provider workflow, installation, and route/cap experiments require explicit authorization.

Removing `extensions/subagents/index.ts` and reloading removes the managed tool, `/subagents`, context projection, observation hooks, and observer-event publisher. Shutdown aborts and awaits this instance's known work before releasing resources. User-owned managed and historical diagnostic data is not silently deleted or converted into ordinary missions. Other extensions, parent sessions, source files, and user routing/settings remain independent.
