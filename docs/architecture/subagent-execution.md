# Managed Subagent Execution

`csheng_subagent_sessions`, registered by `extensions/subagents/index.ts`, is the runtime managed transport. The supported collaboration contract is version 4. Historical one-shot names and unsupported version envelopes are recognized only for exclusion, not decoded by current consumers; see [Subagents](subagents.md). Pi owns each native agent loop and session append. The parent owns decomposition, permissions, review adjudication, repair instructions, candidate application, and acceptance. The extension does not infer or advance that semantic workflow.

## Requests and authority

| Action | Contract |
| --- | --- |
| `create` | `requestId` and one to ten tasks; captures and pins immutable Git input before admission. TUI/RPC default to an accepted submission receipt, not a completed report. |
| `continue` | `episodes` with handle, requestId, expectedEpisode and message. Reuses the same logical identity, purpose, prepared Git input, workspaces and native history; it does not implicitly expand access or rebind inputs. |
| `inspect` | Optional handle or runId; reads bounded state without a model. Run views preserve their original episodes even after an early task is repaired. |
| `join` | runId; waits for its terminal result. Cancelling this wait does not cancel execution. |
| `cancel` | runId and optional taskId; explicit execution cancellation. Task cancellation during candidate freeze returns too-late. |
| `refresh` | Handle and expectedEpisode; explicitly integrates new inputs into the idle session's prepared workspaces without discarding pending edits. Conflicts preserve both versions. |
| `apply` | Handle, expectedEpisode and candidateId; explicitly integrates a frozen multi-root candidate into its pinned target worktrees, not their indexes. Per-root outcomes distinguish completed, blocked, unattempted and unknown work; partial application is not complete delivery. Does not refresh task input or accept work. |
| `close` | Handle, expectedEpisode and optional retain/discard disposition. Discard removes exact-owned worktrees, refs and scratch while retaining registry/native evidence. A retained closed session may later be discarded; incomplete release remains visible and retryable. |

Print/JSON one-shot hosts default to foreground execution; interactive/RPC calls may also request `mode: "foreground"`. Git checkout preparation follows admission; dependency/environment preparation is task-owned, not dispatch work. Capacity and explicit locks are session-scoped across submissions, while the existing graph scheduler retains predecessor ordering. No polling, automatic apply, retry, recovery, or semantic acceptance is added.

Input is action-specific and closed: arbitrary paths cannot replace handles, and duplicate handles, unknown fields, invalid versions, or oversized input are rejected. The provider-compatible flat schema documents each action's required fields; missing-field failures retain the valid requested action and name the missing fields. An unrecognized action is null in the current result schema, rendered as a failed request rather than a fabricated inspect. Repository trust and owner/branch checks precede access. Fresh episodes recheck repository admission, routes, hard execution bounds, and capabilities. A selected range is not additional user authority. A task cannot change persistent route defaults, silently expand its grants, or take over another owner's lifecycle resources.

The default native launcher is checked before allocating/accepting a new episode. It uses the current executable and existing CLI script, never an unverified PATH/latest fallback. On Linux a deleted or replaced installation path can reuse the still-running executable inode through `/proc/<parent-pid>/exe`; an unrecoverable entry returns `launcher_unavailable` with a restart hint rather than silently choosing another runtime version. Explicit custom executors own their invocation. Reloading extensions alone does not replace the parent executable.

A task declares absolute read and write grants. One logical session may write several Git roots and read other Git or non-Git evidence. Write grants are prepared as isolated worktrees and frozen as one candidate bundle. Admission pins each root's physical root, Git-dir, and common-dir identities; later replacement or alias retargeting fails closed rather than redirecting the session. Different linked worktrees do not share input merely because their common directory matches. Grants do not add authority beyond the declared paths and do not change the origin repository, session, or branch that owns the registry, capacity, and lifecycle actions. Unsupported older records are identified and left untouched. Role does not make a grant read-only or writable. The parent may explicitly grant a reviewer a candidate's private Git-contained source or exact files when it needs pre-apply review; the extension does not automatically project one child's state into another or treat a review report as an apply decision.

Persisted read grants are revalidated before accepting continuation and again during submission preparation. Replacement, deletion or loss of canonical identity returns `capability_invalidated` without consuming another episode or launching a child. A change after admission still fails closed in child file/typed-Git guards. A structured `csheng-subagent-capability-failure` marker in the current owned native append range preserves that classification instead of generic `incomplete_report`; old episodes and tool-output prose cannot provide the marker. Verify the intended roots and explicitly create a new binding when needed; neither continue nor automatic retry silently reauthorizes replacement roots. Task-owned temporary inputs must remain available while dependent work is active.

Independent runs may overlap under shared global/role capacity. Mutation of each session remains serialized. Apply acquires the actual destination resources in deterministic order: disjoint destinations may progress concurrently, while shared destination mutations serialize. Known in-process root registry writers queue; foreign or unknown disk locks still fail closed. Hard predecessor edges express required upstream outputs, never mere phase order or an intervening parent decision. Edges pass reports, not candidate files. File-dependent successors require explicit parent apply between dispatches. Overlapping selected write ranges do not serialize isolated workspaces; explicit resource locks still protect shared external resources.

### Action example

For an already authorized API-and-client change, one task can declare both writable owners and a separate read-only specification. The paths below are illustrative; replace them with resolved authorized roots.

```json
{
  "action": "create",
  "requestId": "RequestA",
  "tasks": [{
    "id": "AgentA",
    "role": "worker",
    "objective": "Update the API and its client together; verify their real dependency",
    "access": [
      { "permission": "write", "scope": ["/workspace/api", "/workspace/client"] },
      { "permission": "read", "scope": "/workspace/specification" }
    ]
  }]
}
```

`AgentA` remains that session's outward ID. Copy the returned `runId` to `join`; copy the returned candidate ID and current episode to `apply`. A conflict in the client does not undo an applied API root or mean the report was incomplete. Inspect that same session, authorize the scoped repair and verify its changed result. Do not fabricate a new handle from the task name, append an episode suffix or manage an internal workspace ID.

After execution and integration are independently settled, `close` with `handle: "AgentA"`, the current `expectedEpisode` and `disposition: "retain"` closes execution while keeping its owned resources. A later `close` for that same ID/episode with `disposition: "discard"` releases them. Inspect and retry only the remaining owned resources if release is partial; neither close operation accepts the business outcome.

## Trusted host tools, not an OS sandbox

A managed worker has Pi-compatible `read`, `grep`, `find`, `ls`, `edit`, `write`, and `bash`, including native schemas and image reads. Its tools share the session's explicit source-to-prepared root mapping and a session-local FIFO. Bash, source edits, local tests, and repair can therefore observe the same bytes. Existing tools and dependencies are used; the extension does not provision containers, packages, binaries, credentials, or network services.

This is trusted host execution. File-tool guards, private directories, filtered Git defaults and candidate checks are not OS restrictions on bash. They do not isolate host credentials, network, filesystem access, or hostile process escape. Access rules pair `permission: read | write` with one absolute path or a nonempty path list in `scope`; write includes read. The retired `repository`, `writePaths` and `externalReadRoots` declarations are not alternate grant channels. Native file tools enforce the selected ranges and exclude managed Git metadata. Candidate freeze checks actual changed paths; apply also checks the resulting merged destination paths, including parent-side renames. Parent instructions and applicable external controls remain necessary for host-side authority.

Bash uses an ordinary POSIX process group, waits for operation cleanup, and terminates its known descendants on cancellation, timeout, or exit. Managed native search processes are also drained on shutdown. Unconfirmed writer cleanup latches failure; a candidate cannot be frozen merely because an assistant said it finished. This is normal process cleanup, not an adversarial containment guarantee. The mandatory native `csheng-worker-lifecycle` ready/stopped pair is separate from optional performance markers.

## Read-only Git evidence

Tool availability follows access grants, not role or child identity. A read grant includes search, Git read, and shell. A write grant adds edit and write. The separate `git_read` request chooses `status`, `diff` (`commits`, `index`, or `worktree`), single-file historical `show`, or bounded `log`; it supplies an authorized repository selector and literal owner-relative paths. Commit/ref inputs resolve to exact commit IDs, and `show` returns a blob ID. `git_read` itself exposes no arbitrary argv, shell, checkout, apply, fetch, configuration mutation or additional grant. Separately available host tools remain governed by explicit task authority and the trusted-host boundary.

Git metadata admission permits ordinary repositories and registered linked worktrees, rejects unsupported layouts, external/symlinked object stores, alternates, grafts, config includes, filters, partial clones and worktree-specific configuration, and ignores replacement objects throughout Git phases. Parent symlink traversal is refused; historical symlink blobs are read literally, never followed. External read subdirectories remain narrow grants. External diff/textconv, pagers, hooks, fsmonitor and network protocols are disabled; mutable content-filter/encoding declarations fail closed. These checks are a typed capability boundary in a trusted host, not an adversarial filesystem-race sandbox.

Historical gitlink changes retain short recorded commit deltas without submodule recursion. Mutable queries involving scoped index/HEAD gitlinks are explicitly unsupported rather than inspecting another Git store. Binary or attribute-suppressed patches return incomplete/unsupported evidence. Mutable operations fingerprint scoped source/index/HEAD before and after; detected drift discards output. Equal endpoint fingerprints are not a transactional snapshot or acceptance judgment.

Results have explicit completeness, a 64 KiB UTF-8-safe text limit, bounded paths/inventory/metadata, at most 100 log entries and 2,000 show lines per request; subprocess output is bounded at 1 MiB and each Git process at 30 seconds with cancellation. Git stays in the managed child's process group for owner shutdown. Unavailable or incomplete output must not be represented as a full diff. Delegators supply exact accessible patches/blobs or verified Git query capability, accessible review rules, and current input identity; a continuation alone does not refresh a captured source snapshot.

## Source and dependency state

A fresh independent index captures current visible tracked and non-ignored files, including staged/unstaged/untracked content without changing the parent index. Git trees and internal commits are pinned by exact-owned refs; no user branch commit is created. Each selected writable repository has a detached linked worktree with its own index and that repository's shared Git object database. The logical session stays singular across those prepared roots. The `.git` file and administrative identity are validated as linked-worktree metadata, not mistaken for a private repository directory. Managed Git commands suppress inherited Git configuration, hooks and filters; unsupported source types fail visibly. Trusted bash can still access host resources and shared Git metadata: this is not an OS sandbox.

Current worker input manifests retain Git workspace identity only. Dependencies are neither copied, traversed, hashed nor certified by dispatch, refresh or commands; historical dependency-snapshot formats are not part of the current collaboration contract. Project/Git ignore rules determine ordinary source/candidate membership; a package-directory name has no special write prohibition. Workers prepare their own local environments only when their authorized task needs them, using existing project commands and tool-owned caches. Dispatch does not install dependencies, configure global caches or create shared mutable mounts. Source-link, Git metadata and candidate ownership checks remain independent.

Continue never refreshes input implicitly, including a cancelled queued task that has not yet checked out its pinned input. Explicit refresh performs Git three-way integration only while idle, without changing ignored worker-local dependency installations. Candidate freeze discovers additions, deletions, renames, executable modes, binary changes and contained symlinks relative to that fixed input; Git/project ignore rules exclude ignored environment files. Command outputs and auxiliary files belong in scratch. Failures retain diagnostic state rather than silently resetting, reinstalling, or recapturing input.

## Registry, native continuity, and replay

Child startup leaves system-prompt construction and `APPEND_SYSTEM.md` discovery with Pi. The child hook merges the selected native append text with its code-owned role instructions; it does not replace the base prompt or pass a role-only CLI append that suppresses file discovery. This applies to read-only children and managed workers independently of `inheritSkills`. Pi selects a trusted `.pi/APPEND_SYSTEM.md` in the child source before the agent-directory file; it does not combine those two files or import a parent-only ignored project append from `sourceRoot`. Role and append text are rebuilt through the native hook for each episode without accumulating copies in resumed history.

Private data lives under `<agent-dir>/subagent-managed-sessions`, separate from both ordinary Pi sessions and one-shot diagnostic retention. New records, batch caches and tool envelopes use collaboration contract version 4. Older records are excluded without interpreting their task or candidate structures. Recovery reads evidence without replaying executions; interrupted or unknown writers require explicit reconciliation. The admission-selected alphanumeric task/session ID is preserved across create, continuation, cancellation, results and retained state; run and candidate IDs identify distinct objects, while episode is a separate counter. Each owned session directory holds its registry, native JSONL, prepared root collection, scratch and optional episode observations. Native Pi IDs and Git object IDs remain opaque external correlation values, not reformatted product IDs. Batch request records are separate. Directories/files use private permissions; writes use exclusive locks and staged fsync/rename. Unknown lock ownership is not reclaimed automatically.

There are at most ten open logical records per repository/parent session, including records on sibling branches, and at most 256 episodes per record. Close releases open-record slots, not all retained history. Close/discard removes owned source, scratch, candidate, and input-staging artifacts while retaining closed registry/native evidence; it never undoes an already exported prefix. No global storage inventory runs on normal actions or replay. Source/candidate and registry bounds remain independently enforced, not OS disk quotas. Native finalization streams bounded JSONL lines and validates framing, ownership, lineage and post-read stability without rejecting cumulative native history size or row count. Optional observation projection remains bounded (including its 32 MiB native-read limit) and may be unavailable without invalidating execution. Required-data I/O and integrity failures remain visible.

Normal actions, startup, and replay no longer scan the entire managed root or emit aggregate storage warnings. Unsupported envelopes are excluded without reading historical warning or task payloads. Per-workspace, registry, native and candidate limits remain enforced. No idle TTL, background scan or automatic storage cleanup exists; a separate estimate/cleanup CLI is not part of this implementation.

Cleanup is user-owned. Close unneeded handles with `disposition: "discard"` to remove working files while preserving registry/native history. A full reset is a separate explicitly authorized operation requiring coordination with every affected owner and a decision about retained evidence. Version exclusion does not require clearing old state; ordinary source implementation, failed checks or successful close are not reset authority. Applied repository edits and route settings are separate. Never delete individual registry/native files to bypass integrity checks or perform a reset while managed writers are active.

Each episode starts a native Pi print/JSON child with the same native file and prepared-root bindings, without an implicit task-lifetime deadline. The session-owned supervisor may outlive its submission tool call, but there is no persistent RPC child, detached mission, automatic resume, or reconstructed prompt history. Pi performs compaction, tree/fork behavior, and native appends. Structural readers accept legal `context_edit` and ancillary entry evolution without a closed type allowlist; malformed framing, IDs, lineage and cwd remain rejected. Stream completion uses authoritative final-message, executed-tool and settlement evidence. Oversized redundant `agent_end` aggregates can be discarded without poisoning those signals, and failed/aborted unexecuted proposals do not create phantom active tools. Actually started tools still fence completion. The parent side reads the physical native append range without opening or repairing the session. A changed leaf, copied/forked owner, other repository, unknown request outcome, or interrupted writer does not gain continuation authority.

At acceptance, the role's effective `inheritSkills` boolean is stored on the queued record and used for that episode even if configuration changes before launch; later accepted episodes resolve again. The already-loaded effective parent Skill catalog owns native exclusions and precedence only for its own source repository. Every other prepared repository discovers its own applicable project catalog, even when it contains the origin as a nested checkout; neither primary-root selections nor primary-root suppression silently replace another root's catalog. Only selected project Skill paths that belong to the captured Git input are retained privately across continuation, even if a later parent resource reload removes the original files; explicit refresh recaptures that selection. Ignored private project guidance instead follows the current effective parent catalog on each episode and is never treated as snapshot membership. Their paths are remapped to the captured source, and only selected canonical Skill file/directory paths go through CLI. Direct service callers without a parent catalog use Pi's public non-installing Skill parser with project-before-user fallback and cannot infer package-specific enabled resources. Captured repository Skill membership and bytes take precedence over mutable parent source, while ignored private and user-installed guidance is read at its owner. Actual Skill bodies/references remain on-demand reads behind a separate read-only guidance grant pinned to selected physical owners. Native context discovery remains active independently of this switch; original-project ancestors precede the child snapshot's selected repository override, while managed-storage ancestors are omitted. User-installed and trusted private resources outside the captured Git input can change between episodes. The guidance copier does not copy parent conversation history, credentials or arbitrary read-evidence project settings. The native host and explicit access determine the eligible configured tool catalog; role or child identity alone does not remove otherwise eligible operations. The worker kit claims a builtin name only after configured `session_start` registrations have finished, so an ordinary same-name override registered there keeps its implementation and schema. Host-side guidance discovery never provisions a package; the unchanged Pi subprocess still follows its own configured startup package/offline policy. This is a trusted-host guard, not an OS sandbox or shell network policy.

A terminal request replays committed episode evidence without another launch, usage charge, or current route lookup. Each returned current-version transport envelope has fresh bounded request telemetry: parent owner and invocation identity, start/duration, known task widths, actual launches, replayed episodes, and only actually observed extension/configuration epochs. Each episode separately retains its original execution provenance, route, and the actual `inheritSkills` boolean. Unavailable attribution stays unavailable rather than being reconstructed from current configuration or a historical record. Inspect, parse refusals, and replay do not load configuration solely for attribution; their configuration epoch can be unavailable. Replay metadata describes this invocation, not another execution of the historical episode. Authorization still applies. The cached view is historical, not a fresh filesystem validation; use inspect for current state. Request errors are separate from the prior committed result. An unknown outcome is not automatically replayed. After a child returns, native validation, candidate freeze, and required result save are separate finalization stages: a failure preserves recorded child output, usage, duration, and execution status while making the overall result failed and non-applicable. The final registry commit uses an owned pending marker so a post-rename durability error cannot expose an interim successful worker candidate; uncertain persisted state remains non-actionable across replay. A missing or historically zero duration without execution provenance is unavailable, not a known fast run. Native parser rejection reports a bounded reason category without exposing history contents. Quiet successful non-retrying compaction can retain a valid report, but fresh settlement and closed activity remain required; failed, aborted, or retrying compaction cannot resurrect stale output.

A bounded ephemeral current-owner index exposes handles, episodes, state, and candidate metadata, not reports or private paths. It respects project trust and active tools, neither enables disabled tools nor resumes a task, and native history remains authoritative rather than a copied summary. The index is projected once for a new native user-message occurrence actually prepared in model context, and once per recovery boundary: session start, tree navigation, and successful compaction. Receipts, withdrawn/replaced queue drafts and historical context do not open input windows. Pi 0.86.0 queued or mixed-source occurrences have no authoritative source identity; they may open the same non-authorizing reference window, never claim human intent or permission. Unambiguous ordinary extension controls do not open windows. No receipt-text matching, FIFO or human-first inference is used. Structural message digests confirm native-event participation in the host's cloned context, not final wire content after arbitrary later transformations. The projection remains independent of workflow, and explicit inspect/tool guards remain authoritative. A failed or retried provider request keeps the projection pending so the retry still carries it, and settlement clears it. Normal same-process reload and context rebuilding therefore restore the projection only through those boundaries instead of on every request.

## Candidates and recovery

Unapplied C1 and C2 are both compared against the explicit input base B0. Apply does not change that base. An explicit refresh establishes a new input base for later repair. A complete successful report without actual changes produces no candidate.

Freeze creates immutable Git candidate objects and validates source identity, changed paths, environment and byte limits. Apply uses Git three-way merge against a fresh capture of the current parent worktree. Compatible parent edits and renames are preserved, conflicting content is not overwritten, and the parent index is unchanged. Candidate paths remain immutable and root-qualified in aggregate projections; each root retains Git-relative paths. Apply records its actual integration footprint, including allowed renamed destinations or an empty no-op footprint. The whole bundle's target and candidate identities are checked under the destination locks before any target write. A clean per-root pre/post integration journal is retained before mutation; conflict results are not executable journals.

Publication is not a multi-file filesystem transaction or automatic rollback. An uncertain failure marks apply unknown, and `applying`, `partial`, or `unknown` blocks continuation until explicitly reconciled. These recovery and native-leaf checks run on the freshly locked task record, not a stale pre-refresh copy. Reapplying an applied candidate returns its historical outcome without writing again; it does not prove current parent bytes.

Close/retain preserves the working state and evidence. Close/discard removes owned source, scratch, candidate, and input-staging artifacts while retaining the closed registry/native history. It never undoes an already exported prefix. Cached reports, process settlement, candidate creation, and apply status are all distinct from parent acceptance.

## Observation and consumers

Public event hooks record client-observed assistant, streamed thinking, local-tool, delegation-wait, and compaction spans. Each interaction uses an opaque process clock and origin. Missing, backward, nonfinite, duplicate, or unclosed endpoints remain incomplete. Final thinking blocks without streamed endpoints do not become complete zero reasoning. Ordinary parent turns, idle shutdown, and inactive delegation tools write no parent observation. Hooks own no timer, UI slot, dispatch, provider payload, or model configuration.

Native v1 observations contain direct assistant/compaction/branch-summary usage, owner/entry identities, configured child tools/context window/capability hash, and scalar command endpoints/status. The current markers copy neither command text nor prompts. A failed summary without usage is unknown, not free. A structurally valid owned native range can retain usage, commands, and capabilities without a terminal timing marker; missing timing stays unavailable rather than erasing the other planes or inventing zero duration. Partial physical tails, owner/leaf drift, and unreadable ranges still fail closed. Retained usage describes committed recorded rows, not an assurance that a forcibly stopped in-flight provider request has a complete bill. Configured tool evidence is host state, not the final provider payload after later handlers. Usage remains Pi/provider-reported; there is no pricing estimator, server-utilization inference, or provider-quota estimate.

Worker command markers use version-two domain-separated hash keys for nonempty host tool-call IDs bounded to 4 KiB UTF-8. Host IDs are not validated as managed handles. Current observation projections declare `commandCorrelationVersion: 2`; command correlation is an internal attribution field, not a second model-facing session identity. Duplicate, unknown-version, or unmatched markers retain partial command coverage. There is no default command timeout or cumulative command-count/output execution budget. Explicit command timeouts and cancellation remain; bounded command markers and output projections do not terminate otherwise healthy execution.

Optional observation sidecars are bounded to 64 KiB per episode and are not part of the required registry, request, or terminal ACK. No aggregate storage advisory reclaims sidecars. Missing/corrupt caches hydrate as unavailable; an optional write failure cannot invalidate a candidate or committed result. Native history, source integrity, required lifecycle evidence, and candidate failures are never waived as telemetry failures.

The evaluator's `observations` section consumes owned physical parent windows and child projections, deduplicating native owner/entry and logical handle/episode identities. Copied fork prefixes, nested aggregates, replay, inspect, and repeated reads do not create new usage. Prior valid episode evidence survives a missing cache on reread; conflicting stable evidence fails closed. Parent usage and child usage are separate. Cross-run worker union requires matching clocks/origins; child reasoning/tool/compaction summaries sum per-episode measurements as effort, never an unrelated-clock union. Unattributed wall gaps are not asserted user idle.

Evaluation selects the explicitly supported collaboration version before interpreting nested payloads. Unsupported records are excluded separately from malformed current records; historical one-shot results do not contribute launches, successful outcomes or current coverage failures. `managedDispatch` reads current structured invocation facts even without a settled parent observation window. Admission receipts and owner-tagged terminal execution events are distinct; terminal events own launch and queue/preparation/workspace/child timing. Replay, inspect, join and repeated root-status transitions do not duplicate native usage or logical candidate counts. Per-root apply/recovery/release status is a separate bounded projection, not another launch or applied candidate. Conflicting current facts fence timing, and unavailable cross-turn timing remains unavailable. Epoch matching uses recorded effective revision pairs, never inferred mtime or current settings. Optional explicit `--disposition` JSON declares parent acceptance and bounded entry scope; missing or null endpoints/repair counts stay unknown. Such a declaration neither changes runtime state nor applies to every candidate in a wider report automatically. See the maintainer metric schema for exact fields.

Managed tool content is bounded parseable JSON with every handle, episode, candidate identity, and available submission `kind`/`runId`/`generation` preserved before report truncation. `join(mode: foreground)` normalizes to canonical join; async mode on join is rejected. TUI results distinguish request refusal, stored idle/interrupted/closed state, episode outcome, report completeness, apply and resource release. Model content, retained session views and their actual themed rendering expose bounded per-root destination, recovery and release outcomes rather than collapsing partial work into a success count. Model content and both collapsed/expanded TUI include the actual provider/model/thinking when recorded, including failed episodes and replay. Runtime output and the ephemeral index do not emit acceptance pseudo-state; acceptance is parent-owned. Offline `parentAccepted: null` still represents missing explicit disposition evidence. Foreground activity uses Pi's tool-update channel. Async activity uses session observer snapshots instead of invoking the settled submission's progress callback. Terminal facts are persisted before publication and wake. While asynchronous work is outstanding, a public command-context idle waiter spans agent settlement and manual compaction; the early idle flag is not a completed-settlement signal. Pending events are coalesced without queuing a provider-triggering follow-up while the parent is busy. At delivery, current durable owner/branch/run/generation/episode state and consumed terminal receipts are checked: joined, inspected, closed or already-notified episodes do not wake again, while unobserved members of a mixed batch remain eligible. Captured agent/compaction abort leases remain checked through delayed failure consumers. User input, owner changes, shutdown and abort/error fence automatic wake; suppression never removes execution evidence or accepts work. The workflow consumer binds evidence to dispatch-time contract/attempt/input, reconciles terminal-before-receipt and later input changes, and never promotes historical inspect/join results to a newer attempt or contract. In TUI mode the core publishes bounded current-version observer snapshots including a truncated assignment headline and current tool names. Default-loaded `subagents-ui` is a read-only `/subagents-ui` and `Ctrl+Alt+F` session overlay. A separate versioned core query enumerates retained same-repository/parent-session registries, including closed and labeled off-branch history, and reads saved episode observations without mutation or raw-native fallback. Handle identity survives continuation; deduplicated recorded usage and accepted-episode counts are independent of history pages and retain incomplete/unavailable coverage. Fresh live rows remain separate from unconfirmed persisted running state. Lifecycle invalidation refreshes the cached history projection; ordinary heartbeats do not rescan it. Read visibility does not relax any operation's owner/branch/trust guard. See [Subagents UI](subagents-ui.md) for scoped caches, late-reply recovery and bounded redacted query diagnostics; keyed footer status, below-editor widget, and custom completion entries stay off by default. `status-footer` and `work-timing` retain independent TUI contracts. `work-timing` retains its independent v1 parent-only TUI semantics.

## Accounting boundary

Pi can include nested LLM work in footer, `/session`, and RPC totals when a tool returns top-level `usage`. These subagent adapters do not currently supply that field. Their `details.usage` and native/evaluator aggregates are separate evidence, not automatic additions to the parent Pi total; provider-side accounting of child calls still applies. Never add cumulative replay/inspect observations to parent assistant usage or treat missing usage as zero. Native billing forwarding is not implemented.

## Verification and removal

Deterministic tests cover contracts, linked worktrees and ignored-environment preservation without traversal, real local command test/repair, queued cancellation and pinned-input continuation, concurrent refresh/uncertain-apply races, root writer serialization, shared capacity, replay, immutable Git candidate integration, shallow unsupported-version exclusion, partial resource release and producer/consumer ownership. A real RPC-mode Pi SDK host with synthetic parent provider and native child processes exercises overlapping tasks, independent parent work, event-driven workflow waiting, early apply, explicit refresh, same-native-history repair, late sibling ownership and exact-owned cleanup. It makes no provider calls and grants no semantic acceptance. Disposable synthetic-provider tests exercise both the development Pi API and installed CLI, native append/reopen, same-process reload, compaction, actual tool progress, and cross-episode accounting. They are not evidence of economic benefit or successful real-provider semantic delivery.

Temporary/installed subagent probes discover the managed tool and assert its absence when the extension is disabled, without inference. The separately gated live script is not managed continuation acceptance and is not a verified package co-load proof; parent owns acceptance of that lane. Provider workflow, installation, and route/cap experiments require explicit authorization.

Removing `extensions/subagents/index.ts` and reloading removes the managed tool, `/subagents`, context projection, observation hooks, and observer-event publisher. Shutdown aborts and awaits this instance's known work before releasing resources. User-owned managed and historical diagnostic data is not silently deleted or converted into ordinary missions. Other extensions, parent sessions, source files, and user routing/settings remain independent.
