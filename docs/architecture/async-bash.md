# Async Bash

`extensions/async-bash/index.ts` is the TUI/RPC background job path for Pi's builtin `bash` tool. It does not replace the host agent loop and does not schedule model wakes. A terminal that the tool call itself does not return is published for [loop notifications](notices.md).

## Owner

Pi's builtin `bash`, created through `createBashTool` / `createLocalBashOperations`, waits until the process exits; its timeout and abort kill the process. The extension detects the effective tool source at runtime rather than treating workstation configuration as product truth. When it claims `bash`, it runs commands through that same exported `createLocalBashOperations()` / `BashOperations` seam: Pi keeps shell discovery, spawn, output streaming, process-tree teardown and worker-shutdown tracking, and the extension keeps the execution promise, checkpoint, optional hard timeout and observation state. There is no second process backend and no wrapper-owned launch or kill command. PowerShell, MCP tools, and any extension that has already registered `bash` are outside this path.

The extension claims `bash` only when the merged tool source is still `builtin` and the session mode is `tui` or `rpc`. Print and JSON keep the native draining tool, with its native `timeout` support. Retained-only parameters are rejected before command effects in these modes; no post-exit wake is promised. A non-builtin `bash` is left in place, and the extension emits one `async-bash.execution` event with `phase: "unavailable"`. It does not start a second shell to bypass that owner.

Managed child processes are print/JSON Pi processes. Their shell calls stay on the native draining tool, so this extension does not return `running` from a child tool call or change candidate freeze.

## Execution

Each start makes exactly one native invocation with the tool call's cwd and environment. `shellCommandPrefix` is prepended once to the executed command, as the native tool does, while the label and human preview use the command alone. A started command gets an execution id, a bounded output tail, and a checkpoint. The id is not a process id. The checkpoint exists so a long or hung command surfaces to the model instead of silently holding the session, while a legitimately long command keeps its progress. `deadlineSeconds` sets it, 600 seconds by default. When the checkpoint passes, the process keeps running, the execution becomes overdue, and one checkpoint notice reaches the model with the elapsed time, time since last output, recent output and the choices: `renew` moves the checkpoint and clears overdue, `cancel` stops the process, and leaving it running sends no further checkpoint notice while its completion is still delivered. An open foreground window or wait on that execution returns the overdue view itself instead of a separate notice. `timeout` is the opt-in hard lifetime: only an explicit `timeout` kills the process at a fixed time, recorded as status `timeout`. Explicit durations are not clamped to a product ceiling. A duration must be finite and representable: NaN, Infinity, non-positive values, sub-millisecond values, and values that are not a safe millisecond count are rejected. A checkpoint or timeout must also fit in a Date timestamp. Delays above the native timer ceiling are armed as cancellable chunks, so the runtime does not collapse them into an immediate timer. A timeout aborts that same native execution, so its process and children are torn down by Pi's abort path. It is not a second launch. The extension does not pass an invocation-time timeout to the native operation, which is why the checkpoint can be renewed for the running execution.

A non-background call may stay in the tool call for a foreground window. The default is 2 seconds. An explicit positive finite `foregroundSeconds` is honored with no product cap. If the command exits in that window, the call returns that terminal result. If it is still running, the call returns `status: running` and the process continues. The window also returns early, with the process still running, when the main loop has other work: a user steering message submitted in this run, or another execution's notice ready for delivery (see [main-loop responsiveness](notices.md#main-loop-responsiveness)). Follow-up input that the user queued for after the run does not shorten it. `background: true` returns as soon as the execution is running. Output collection begins at spawn, not when the deadline fires, and the native shell has no terminal stdin, so a command that reads input sees end-of-file rather than waiting for a terminal. An aborted start still does not spawn, and abort during the foreground window still cancels the process that already started.

`action: "inspect"` reads the current execution immediately and does not start or wait. A running snapshot has a null exit code. A terminal snapshot has the actual exit code, which stays null when the process did not report one. `action: "wait"` waits only for that execution, or until `waitSeconds` or the tool abort releases the wait. Omitted `waitSeconds` is 180. An explicit positive finite duration is honored with no product cap. A wait also returns at that execution's checkpoint and yields to steering or another ready notice like a foreground window. Releasing the wait does not kill, cancel, or renew the process. `action: "renew"` moves the checkpoint of the same running execution. `action: "cancel"` stops it. Host session shutdown stops running executions and records `interrupted`. An ordinary turn settlement does not.

Long waits, foreground windows, checkpoints and timeouts share `scheduleDelay` in `extensions/shared/duration-timer.ts`. That helper is also the cancellable timer for a parent join budget that must honor an explicit duration without a product cap. A running tool result tells the model that inspect is one concrete progress question, not a poll. If no independent work can run, the model may end the turn with the execution pending and rely on the one terminal notification. Ending the turn does not claim success or require marking the task blocked. An explicit wait remains available when it serves a real dependency.

A running call has one tool result. The terminal state is not written back onto that call id. Unknown exit codes stay unknown and are not reported as 0. Cancel, timeout, and shutdown settle when the native operation settles after its process closes, so already-written output is not dropped at the abort call. Observer failures do not fail or strand the execution. An already-aborted start does not spawn; a native operation that refuses synchronously before spawning leaves no execution record. Terminal records stay for the owner process so Jobs can list every background job; each output tail remains bounded. Commands and wakes are scoped to the session and branch; a real session or branch switch interrupts the old running owner and keeps that scope's final result inspectable. Idle and compaction do not shut executions down.

## Model delivery

Async Bash publishes running and terminal facts. It does not call Pi's send API. A foreground return, inspect, or wait marks that terminal observed so it is not also notified. Start with `{"command":"bun test"}`. Control with `{"action":"inspect","executionId":"exec_example"}`. An execution id without an explicit action, `run` with an execution id, a control without its id, a command on a control, or a non-positive timing value is rejected before any process start or target change. Command text is never parsed as an action.

[Notices](notices.md) delivers an unobserved terminal once, including while another execution remains running, and an unobserved checkpoint once as its own notice. A terminal supersedes an undelivered checkpoint of the same execution. Print/JSON and an unclaimed bash owner do not wake. The execution record remains inspectable if delivery fails.

The event `version` is 1. Fields are `executionId`, `owner` (`pi-bash`), `sessionId`, `branchAnchor`, `toolCallId`, `phase`, `status`, `exitCode`, `deadlineAt` (the checkpoint), `timeoutAt`, `overdue`, `checkpoint` (reached-checkpoint count), `truncated`, `outputTail`, and `notification`. Terminal and `checkpoint` notifications are `idle-wake-or-next-request`. `started` and `renewed` are `not-a-completion`. `unavailable` uses `wake-unavailable` and means this process did not claim bash. Live output remains on `inspect`; the event is not sent per output line.

## Human view

`extensions/jobs-ui/` renders the current parent session and visible branch. Async Bash remains the owner of job facts and publishes a read-only snapshot after those facts change. The view does not start, cancel, renew, or notify the model. An absent, untrusted, or other-owner source is unavailable, not zero jobs. The section is titled Jobs. Its bottom line uses the shared heading grammar with Tasks and Agents, `Jobs (<finished>/<total> done) <running> running`, and omits a zero running count. It warns only for current conditions: an unavailable source, or jobs running past their checkpoint until the model renews or cancels them. A finished failure, timeout or interruption stays a row fact and never holds the heading in a warning state. The bottom section and `/jobs-ui list` show the same background jobs: work that returned still running from the foreground window or an explicit background start, unless `/jobs-ui` has hidden the bottom section. Foreground completions stay out of both. `JOBS_MIN_VISIBLE_SUCCESS_MS` can omit short successful background exits; it is 0, so duration does not filter them. The bottom section limits visible rows and shows running jobs before stopped ones, then start time ascending. A fullscreen header click expands or collapses inline rows on the shared panel row grammar: a state glyph (`◐` running, warning-toned past its checkpoint, `✓` exit 0, `✗` non-zero exit, `?` unknown exit, `⊘` timeout, cancelled or interrupted), a bounded first-command-line preview, the elapsed time, and a detail column with `past checkpoint` and time since last output while running, or the non-zero exit code or terminal status otherwise. The preview is clipped to the available width while reserving the status fields; internal execution IDs are not shown. Durations use spaced units (`46s`, `3m 46s`, `1h 3m 46s`) and subsecond durations use milliseconds instead of rounding to zero seconds. `/jobs-ui expand` and `/jobs-ui collapse` provide the same control in regular mode. This fold state and manual hiding survive updates independently of Tasks and Agents; header clicks neither open a dialog nor take editor focus. A terminal row freezes at close and shows a non-zero or unknown exit code. No output is not stalled, and a process exit is not business acceptance. `/jobs-ui list` opens a central read-only overlay of that same background set for the current session and branch. It pages when the rows do not fit. Opening it does not change bottom visibility or fold, does not start another query, and is not durable history or a view of other tools. Rows that do not fit the bottom section remain reachable there. Toggle/show/hide commands emit an on/off notification, matching the other two UIs. The command preview is session-local observation data, not a model argument or persisted execution-event field; it excludes later script lines/output, strips terminal controls, bounds its length and redacts assignment values and common credential-bearing flags. It is not a general shell-secret detector. Headless modes mount nothing.

## Removal

Removing the extension restores builtin bash for later sessions. The host must run session shutdown before unloading an active owner; shutdown aborts its native operations and awaits their settlement, and Pi's abort path owns process-tree teardown. The extension issues no kill commands, so stopped executions need no further cleanup and unrelated processes are not targeted. No migration or user setting is required.
