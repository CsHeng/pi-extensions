# Async Bash

`extensions/async-bash/index.ts` is the TUI/RPC retained execution path for Pi's builtin `bash` tool. It does not replace the host agent loop and does not schedule model wakes. A terminal that the tool call itself does not return is published for [loop notifications](job-notifications.md).

## Owner

Pi's builtin `bash`, created through `createBashTool` / `createLocalBashOperations`, waits until the process exits; its timeout and abort kill the process. The extension detects the effective tool source at runtime rather than treating workstation configuration as product truth. When it claims `bash`, it runs commands through that same exported `createLocalBashOperations()` / `BashOperations` seam: Pi keeps shell discovery, spawn, output streaming, process-tree teardown and worker-shutdown tracking, and the extension keeps the execution promise, deadline and observation state. There is no second process backend and no wrapper-owned launch or kill command. PowerShell, MCP tools, and any extension that has already registered `bash` are outside this path.

The extension claims `bash` only when the merged tool source is still `builtin` and the session mode is `tui` or `rpc`. Print and JSON keep the native draining tool, with its native `timeout` support. Retained-only parameters are rejected before command effects in these modes; no post-exit wake is promised. A non-builtin `bash` is left in place, and the extension emits one `csheng.shell.execution` event with `phase: "unavailable"`. It does not start a second shell to bypass that owner.

Managed child processes are print/JSON Pi processes. Their shell calls stay on the native draining tool, so this extension does not return `running` from a child tool call or change candidate freeze.

## Execution

Each start makes exactly one native invocation with the tool call's cwd and environment. `shellCommandPrefix` is prepended once to the executed command, as the native tool does, while the label and human preview use the command alone. A started command gets an execution id, a bounded output tail, and a finite deadline. The id is not a process id. The default deadline is 600 seconds. `timeout` or `deadlineSeconds` selects a different positive finite deadline; the shorter explicit value wins. Explicit deadlines are not clamped to a product ceiling. A duration must be finite and representable: NaN, Infinity, non-positive values, sub-millisecond values, and values that are not a safe millisecond count are rejected. An execution deadline must also fit in a Date timestamp. Delays above the native timer ceiling are armed as cancellable chunks, so the runtime does not collapse them into an immediate timer. The deadline aborts that same native execution, so its process and children are torn down by Pi's abort path. It is not a second launch. The 600 second default is the execution deadline, not the observation budget. The extension does not pass an invocation-time timeout to the native operation, which is why a deadline can be renewed for the running execution.

A non-background call may stay in the tool call for a foreground window. The default is 2 seconds. An explicit positive finite `foregroundSeconds` is honored with no product cap. If the command exits in that window, the call returns that terminal result. If it is still running, the call returns `status: running` and the process continues. `background: true` returns as soon as the execution is running. Output collection begins at spawn, not when the deadline fires, and the native shell has no terminal stdin, so a command that reads input sees end-of-file rather than waiting for a terminal. An aborted start still does not spawn, and abort during the foreground window still cancels the process that already started.

`action: "inspect"` reads the current execution immediately and does not start or wait. A running snapshot has a null exit code. A terminal snapshot has the actual exit code, which stays null when the process did not report one. `action: "wait"` waits only for that execution, or until `waitSeconds` or the tool abort releases the wait. Omitted `waitSeconds` is 180. An explicit positive finite duration is honored with no product cap. Releasing the wait does not kill, cancel, or renew the process. `action: "renew"` moves the deadline of the same running execution. `action: "cancel"` stops it. Host session shutdown stops running executions and records `interrupted`. An ordinary turn settlement does not.

Long waits, foreground windows, and deadlines share `scheduleDelay` in `extensions/shared/duration-timer.ts`. That helper is also the cancellable timer for a parent join budget that must honor an explicit duration without a product cap. A running tool result tells the model that inspect is one concrete progress question, not a poll. If no independent work can run, the model may end the turn with the execution pending and rely on the one terminal notification. Ending the turn does not claim success or require marking the task blocked. An explicit wait remains available when it serves a real dependency.

A running call has one tool result. The terminal state is not written back onto that call id. Unknown exit codes stay unknown and are not reported as 0. Cancel, deadline, and shutdown settle when the native operation settles after its process closes, so already-written output is not dropped at the abort call. Observer failures do not fail or strand the execution. An already-aborted start does not spawn; a native operation that refuses synchronously before spawning leaves no execution record. Terminal records stay for the owner process so Jobs can list every background job; each output tail remains bounded. Commands and wakes are scoped to the session and branch; a real session or branch switch interrupts the old running owner and keeps that scope's final result inspectable. Idle and compaction do not shut executions down.

## Model delivery

The shell publishes running and terminal facts. It does not call Pi's send API. A foreground return, inspect, or wait marks that terminal observed so it is not also notified. Start with `{"command":"bun test"}`. Control with `{"action":"inspect","executionId":"exec_example"}`. An execution id without an explicit action, `run` with an execution id, a control without its id, a command on a control, or a non-positive timing value is rejected before any process start or target change. Command text is never parsed as an action.

[Job Notifications](job-notifications.md) delivers an unobserved terminal once, including while another execution remains running. Print/JSON and an unclaimed bash owner do not wake. The execution record remains inspectable if delivery fails.

The event `version` is 1. Fields are `executionId`, `owner` (`pi-bash`), `sessionId`, `branchAnchor`, `toolCallId`, `phase`, `status`, `exitCode`, `deadlineAt`, `truncated`, `outputTail`, and `notification`. Terminal notifications are `idle-wake-or-next-request`. `started` and `renewed` are `not-a-completion`. `unavailable` uses `wake-unavailable` and means this process did not claim bash. Live output remains on `inspect`; the event is not sent per output line.

## Human view

`extensions/bash-jobs-ui/` renders the current parent session and visible branch. Retained bash remains the owner of execution facts and publishes a read-only snapshot after those facts change. The view does not start, cancel, renew, or notify the model. An absent, untrusted, or other-owner source is unavailable, not zero jobs. The bottom line uses the same collapsed grammar as Tasks and shows running/total, the longest running duration, and a failure or interruption marker when one exists. The bottom section and `/bash-jobs-ui list` show the same background jobs: work that returned still running from the foreground window or an explicit background start, unless `/bash-jobs-ui` has hidden the bottom section. Foreground completions stay out of both. `JOBS_MIN_VISIBLE_SUCCESS_MS` can omit short successful background exits; it is 0, so duration does not filter them. The bottom section limits visible rows and shows running jobs before stopped ones, then start time ascending. A fullscreen header click expands or collapses inline rows showing `Bash` plus a bounded first-command-line preview, the recorded state, elapsed time, and time since last output. The preview is clipped to the available width while reserving the status fields; internal execution IDs are not shown. Subsecond durations use milliseconds instead of rounding to zero seconds. `/bash-jobs-ui expand` and `/bash-jobs-ui collapse` provide the same control in regular mode. This fold state and manual hiding survive updates independently of Tasks and Agents; header clicks neither open a dialog nor take editor focus. A terminal row freezes at close and shows the recorded exit code when one exists. No output is not stalled, and a process exit is not business acceptance. `/bash-jobs-ui list` opens a central read-only overlay of that same background set for the current session and branch. It pages when the rows do not fit. Opening it does not change bottom visibility or fold, does not start another query, and is not durable history or a view of other tools. Rows that do not fit the bottom section remain reachable there. Toggle/show/hide commands emit an on/off notification, matching the other two UIs. The command preview is session-local observation data, not a model argument or persisted execution-event field; it excludes later script lines/output, strips terminal controls, bounds its length and redacts assignment values and common credential-bearing flags. It is not a general shell-secret detector. Headless modes mount nothing.

## Removal

Removing the extension restores builtin bash for later sessions. The host must run session shutdown before unloading an active owner; shutdown aborts its native operations and awaits their settlement, and Pi's abort path owns process-tree teardown. The extension issues no kill commands, so stopped executions need no further cleanup and unrelated processes are not targeted. No migration or user setting is required.
