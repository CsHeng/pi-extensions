# Agents UI

`extensions/agents-ui/index.ts` is a default-loaded, TUI-only, read-only session inspector. The core owns retained inventory and recorded accounting; the UI consumes correlated session-view replies and fresh managed observer snapshots. It does not execute children, own cancellation, reconcile registries, write the working row/footer, or persist execution/ownership metadata. Its bounded query diagnostics are separate from task outcomes.

## Surfaces

- Bare `/agents-ui` toggles the above-editor section. `/agents-ui list` and `Ctrl+Alt+F` open a content-fitted floating overlay titled `Agents · session <prefix>…`, not a batch or invocation. A fullscreen header click expands or collapses inline agent rows, not the overlay. `/agents-ui expand` and `/agents-ui collapse` provide keyboard command equivalents; folding and visibility are independent of Tasks, Jobs and Details.
- The central summary shows the live count and total agents in the session. Both inline and central lists use one row per item: `Role: readable task label | model thinking | current action or outcome | elapsed`. The accepted task label stays stable across activity updates. A duplicate title gains a short distinguishing handle; the selection always uses the full handle and episode. A missing label reads `untitled task`.
- Fresh live rows are pinned above history. The activity field shows a started running tool and its redacted target, `generating reply` while assistant text is streaming, or the observed execution phase. The clock measures child execution and freezes when the child stops, including during finalization. A stale observation shows the last measured duration and replaces transient activity. A settled row shows its outcome; cached queued or running state cannot erase the result of that episode. Ten live rows fit at 80×24; a smaller viewport keeps the other identities reachable by arrow.
- H expands or collapses retained history. Up/Down select a keyed agent and Enter opens its read-only detail; Escape returns to the selected list row, revealing its history row if the episode finished while being inspected. Settlement leaves untouched history folded. History includes current-version idle, interrupted, closed and unconfirmed persisted-running records. Off-branch work remains labeled; storage lifecycle is in detail, separate from execution outcome. A successful `close` does not make a failed episode successful. PageUp/PageDown request bounded history pages.
- The panel uses the same transparent rounded frame and one-column inner padding as the Tasks and Jobs lists, with no background fill, an accent title and muted rules. Width is content-fitted with an 80-column preference clamped to the terminal; height and wrapping follow actual terminal cells, including the two frame rows. The right-aligned `×` title mark closes the view under supported fullscreen pointer capture. `Ctrl+Alt+F` also closes it; unhandled keys retain host behavior.
- The above-editor section uses the shared disclosure and accent/warning heading grammar with Tasks and Jobs, `Agents (<settled>/<total> done) <running> running · <queued> queued`, with `?` for an unknown live count and appears when the session has published agent state, unless `/agents-ui` has hidden it. Its bounded inline body uses current read-only observer/session-view facts on the shared inspection row grammar (`extensions/shared/inspection-rows.ts`): a state glyph, readable title, recorded model and thinking level, elastic activity and an elapsed suffix. A narrow row shortens fields to fit real terminal cells. The heading warns only while live or session counts are unknown; settled failures stay on their rows. Detail shows bounded route, usage and call facts, with unavailable records explicit. Status updates preserve folding and manual hiding. Fullscreen title clicks never open Details or take editor focus. The old below-editor live-row widget and keyed status are not mounted. The observer never appends custom completion entries.

Details show the provider, handle and episode, usage, and available call or lifecycle evidence. The first accepted assignment is episode 1 and each accepted continuation advances it once; model turns, tools and replay do not. Retained details show per-root application and release separately from report completeness and the session's aggregate release disposition. A scratch-only release failure must not relabel already released roots, and a session without a candidate can still have owned resources to release. A partially applied bundle is not counted as one completely applied candidate. The structured managed tool result remains outcome authority. Showing retained history does not authorize continuation, apply, close or cancellation. Historical one-shot snapshot UI v1, including its cancellation receipts and completion entries, is not a current surface.

In either TUI mode, `/agents-ui focus` shows and unfolds the inline section and selects its first row. In fullscreen, click an expanded row to select that agent directly. Enter opens that episode's details, Escape returns to the selected row, and a second Escape returns to the chat draft. Header clicks only fold. All three UIs use `/xxx-ui list` to open their central list without changing bottom visibility or folding. The Agents list also opens and closes with `Ctrl+Alt+F`.

## Read scope and delivery

`extensions/agents/session-view.ts` owns the current-contract `agents.session-view.request` and `agents.session-view` events. Requests contain a request identity and page; replies contain the core-derived parent session, branch anchor, generation and retained-projection revision. The core checks project trust and reads only the same canonical repository and parent session. Same-session off-branch records are explicitly historical, while tool mutation retains its existing restrictive branch/owner checks.

Inventory reads existing current-version managed registries, including closed records, without creating storage or changing registry bytes. Unsupported envelopes are excluded before interpreting legacy payloads; exclusion and unavailable coverage remain visible rather than becoming successful history rows. Private/canonical file checks precede reading; identifiable foreign owners are excluded before recursive record validation and episode work, while owned or unidentified invalid records retain uncertainty. History uses 20-row pages, independent of open-session admission limits. Every valid retained handle remains reachable; unreadable storage/records and unavailable accounting are visible, not a complete-looking empty success. Payloads are bounded and strictly validated. The versioned reply accepts at most 16 live rows, independently of the current ten-open-session execution limit.

The core caches retained inventory and saved episode observations by canonical repository and parent-session identity. Branch badges are recomputed from retained ownership anchors, so ordinary parent-leaf changes do not rebuild inventory. Lifecycle changes invalidate the projection and emit the data-free `agents.session-view.changed` notification; an open UI requeries its current page. Heartbeats and ordinary repaint do not scan history. Concurrent queries share a read, and an older owner/revision read cannot replace a newer cached projection.

UI request identities are unique across extension instances. The UI rejects foreign, superseded, retired-generation and mismatched replies, handles rapid navigation and owner changes, and ends visible waiting after four seconds. A same-page timeout or transient display failure retains explicitly labeled cached history without refreshing its live-observation timestamp. The timed-out request remains correlated, so a valid late reply can recover the panel; manual retry or a subsequent lifecycle invalidation supersedes it. Trust loss, owner changes and accepted new generations discard old query visibility. `history_query_failed`, `core_query_failed` and `core_reply_invalid` are explicit failures, not empty successful inventories or execution failures.

Trusted queries append bounded version-one `agents.view-query` diagnostic entries: core delivery records request identity, duration, ready/unavailable state and an optional bounded reason; UI timeout records its source, request identity, elapsed wait and whether cached history existed. The records contain no rows, native prose, filesystem paths, exception text or acceptance. They do not trigger a provider turn, run on heartbeats, change retained registries, or establish successful task completion. Diagnostic-write failure never changes query delivery or recovery.

Reload restores inventory observationally. Persisted `running` or `queued` alone does not establish a live child; no UI read resumes, reconciles, launches or rewrites it. Session start/tree/shutdown dismisses the old overlay and clears its observation/query state. Reopening queries the current session again.

## Live observations and usage

The `agents.observer.v5` event carries bounded current-version live snapshots. Older observer payloads are excluded without converting their rows. A live snapshot is not a complete session-history or total-accounting source. Fresh child lifecycle hooks establish activity; inspection, apply, close and pure replay do not create new live dispatch. A five-second heartbeat keeps active observations fresh, and after fifteen seconds without evidence the UI marks unfinished activity unknown and stops elapsed extrapolation. Closing the overlay stops its timers, not the children.

The core aggregates saved per-episode native observations and deduplicates entries by `(ownerSessionId, entryId)`, including overlapping continuation observations. Session totals are independent of history page. Token metrics and cost expose complete, incomplete or unavailable coverage; incomplete known subtotals are labeled, and unknown values are never silently zero. Missing/invalid observations, identity conflicts, compaction, aggregate-only usage, unknown prices and numeric overflow retain uncertainty. There is no raw native JSONL fallback or claim that partial recorded usage equals final provider billing. Agent detail uses the footer's formatter and grammar, `↑ ↓ R W CH $ RB` (see `usage-metrics.md`). The live lane covers the current episode, the retained lane covers that agent's recorded history, and separately labeled session totals cover all its agents. Each lane has one scope, so `CH` is the prompt-token-weighted mean over that agent's recorded assistant prompts and `RB` sums Pi's per-request re-bills, which native observation attributes per assistant row against the whole native file. Zero fields are omitted, unknown fields are left out of the sums and the line keeps its `partial` coverage label, and an unavailable projection reads `usage unavailable`. Request turns remain in records, observer snapshots and model-facing results; no human-facing Agents line shows them.

## Verification

`tests/agents-session-ui.test.ts` composes real managed storage, the registered core event producer and the registered UI around synthetic execution. Its 37-handle/49-episode scenario covers complete navigation, live pinning, accounting and reload without launch or durable mutation. Store, accounting, session-view and UI suites separately cover owner isolation, continuation/replay, coverage failures, query races and cache invalidation. A thousand-foreign-record regression checks that branch changes reuse one owned inventory/accounting scan; failure, timeout, late reply, generation/reload, trust loss and diagnostic-redaction tests protect recovery boundaries.

`tests/agents-cc-tui.test.ts` runs installed Pi and CC in on/compact modes through a PTY, proving live/settled updates and retained route details while partial tool output is hidden. `tests/agents-ui-tui.e2e.ts` uses installed Pi, a synthetic offline provider and disposable HOME/agent settings. The disposable synthetic-history project is explicitly trusted without changing any real project trust or settings. The test-only `@xterm/headless` terminal decodes the actual PTY output: H, PageUp/PageDown and arrows reach all history while ten live identities remain on screen; resizing the owned PTY from 80×24 to 40×24 and back preserves reachability. It also verifies settlement, keyboard close and the fullscreen close-chip click. An additional no-inference fixture loads all three UI extensions together and checks independent folding, fullscreen pointer selection, keyboard selection in regular mode, wide/narrow row layout, and return from detail to the selected row and the original chat draft. Synthetic PTY stimuli do not claim to launch native children; existing native-session suites own that evidence.

Run `bun run e2e:agents-ui` explicitly, or the non-skippable affected-UI gate `bun run e2e:ui-offline`. The standalone tests skip when installed Pi or util-linux `script` is absent; a skip is not acceptance. Set `PI_EXTENSIONS_UI_PACKAGE_ROOT` to an isolated package snapshot to run the same PTY checks against that candidate, and pair this with `scripts/run-installed-agents-probe.sh <package-root>` for registration/source identity. No real settings or provider network calls are involved.

## Independence

The extension validates data received through `pi.events` and is inert in RPC, JSON and print modes. It must not call `setWorkingMessage` or `setFooter`. Removing it leaves `agent` unchanged. Removing the core leaves the UI safe with unavailable history. `status-footer` and `work-timing` retain independent contracts.

See [Agents](agents.md) and [Managed Agent Execution](agent-execution.md) for execution, provenance, retained ownership and observation contracts.
