# Agent Execution

The seven [Agents](agents.md) tools in `extensions/agents/index.ts` expose collaboration contract version 5. Pi owns the native loops and session appends. The main agent assigns work, coordinates overall progress and retains final acceptance with the user. Peers coordinate work within their briefs, and assigners own decisions about scope, authority and unresolved findings. For implementation, report changes, checks actually run, known problems and unverified parts. The main agent chooses the integration and verification strategy, reusing evidence while its behavior, inputs and conditions still apply.

## Tools and authority

| Tool | Input | Behavior |
| --- | --- | --- |
| `invoke_agent` | `name`, `role`, `prompt`, `access`; optional `workspace`, `may`, `executionProfile`, `thinkingProfile`, `model`, `thinking` | Admit one assignment. TUI/RPC return a submission receipt and run the child under the owning session. Print/JSON observe in the foreground; a one-shot process shuts down its owned execution on exit. |
| `message_agent` | `to`, `message` | Address an agent or `main`. Read the delivery receipt for whether it reached a running agent, is queued, or started an idle agent's next turn. Messages are bounded to 64 KiB UTF-8. |
| `list_agents` | Optional `name` | Read a roster snapshot of visible, unreleased agents: name, role, state, workspace for writers, assigner and latest result summary. A named lookup returns the latest bounded full report to the assigner or main agent; a visible peer gets a summary. |
| `wait_agents` | Optional `names`, `waitSeconds` | Wait for the named visible agents, or the running agents the caller invoked, and return available results within the caller's report permissions. The budget defaults to 180 seconds; explicit finite durations are honored. In the main session, user steering, an agent message to main or another ready notice can end observation early. Expiry or early return leaves execution running. |
| `stop_agent` | `name`, optional `revert` | End the current turn or confirm an interrupted writer's settlement. After settlement, `revert: true` on a shared writer restores eligible last-turn file-tool changes. The agent stays addressable until release. |
| `release_agent` | `name`, optional `disposition` | Close an idle agent. `retain` (default) keeps its files and history; `discard` releases exact-owned private working files and preserves registry/native evidence. A retained release can later be discarded. The name remains bound. |
| `agent_candidate` | `name`, `action: "apply" \| "refresh" \| "discard"` | For an idle isolated writer, integrate the frozen candidate, merge current checkout changes into private input, or discard its private copy and release it. A newer unseen result is shown before mutation; review it before repeating the action. |

Use a name that starts with a lowercase letter and contains up to 64 lowercase letters, digits or hyphens. Names are used once within a main session, across branches and after release; `main` is reserved. Trust and repository, session and branch ownership still gate the operations. Handles, run IDs, episodes and candidate IDs correlate engine records; the model addresses the agent by name and supplies no version. The internal create/continue/inspect/join/cancel/reconcile/refresh/apply/close schema serves the engine, not the model-facing interface.

Each `access` rule pairs `permission: "read" | "write"` with an absolute path or nonempty path list in `scope`. Write includes read. A logical agent can write several Git roots and read independent Git or non-Git evidence. Admission pins physical repository, Git-dir and common-dir identities; replacement or retargeting fails visibly instead of redirecting a grant. Linked worktrees with the same common directory are distinct targets. The original repository, session and branch own the record even when grants reach other roots. Role names and paths do not substitute for user authority.

The role's `may` supplies defaults; an invoke can supply a replacement with all three fields: `message` (list of `assigner`, `peers` with the same assigner, and explicit names), `roster` and `invoke` (booleans). An assigner can message its own assignees and see them even without expanded messaging or roster grants. A child may address `main` when it is the child's assigner and `assigner` is granted, or when `main` is explicitly granted. The main agent and each agent's assigner own stop, release, full reports and candidate operations. Peers get summaries and can send messages as their capabilities allow.

Four invariants hold regardless of role and capabilities: an agent message is the sender's information or direction, never user approval; delivery leaves `access` unchanged; a child grants at most the access it already holds; final acceptance stays with the main agent and the user.

Example: invoke a named writer for an already authorized change. Include any checks and peer ownership in the assignment prompt.

```json
{
  "name": "api-and-client",
  "role": "worker",
  "prompt": "Update the API and its client together; verify their real dependency and report the checks you ran.",
  "access": [
    { "permission": "write", "scope": ["/workspace/api", "/workspace/client"] },
    { "permission": "read", "scope": "/workspace/specification" }
  ]
}
```

## Delivery and turn ownership

A child forwards its agent tool calls to the main session hub over a private Unix socket. The launcher supplies a token for its episode; the child consumes it from the environment before starting shell commands, and the hub derives the caller from that binding. The hub checks access containment for nested invocation. Roles, capabilities and grants enter the child prompt at its turn boundary. The roster stays on demand through `list_agents`.

A message to a running agent enters its next model call after current tool calls; if the turn settles first, a pending message can start the next turn. A message to an idle agent starts a turn. The result follows the initiator: messaging an already-running agent leaves its turn result with the initiator of that turn; messaging an idle agent returns the next result to the sender. Agent-initiated results are bounded receipts, delivered to a running initiator or held until its next turn. A receipt alone starts no turn. The main agent retrieves those retained results through `list_agents`; main-initiated results are eligible for [Notices](notices.md) when not already observed.

Agent messages carry sender attribution. Live messages use Pi custom messages; an idle child's next invocation carries the attributed messages in its turn input. Messages to the main agent use custom messages and can start an idle turn. They remain distinct from user input and do not invoke the user-input suppression path in Notices.

## Admission and observation

Replay identity comes from the host tool-call boundary where the engine admits work. Admission validates access, routes and bounds; known-unlaunched failure unwinds owned queued state and fresh reservations. Failed continuation restores prior idle state under the record lock, preserving same-episode apply or refresh already accepted. Failed ref disposal retains ownership for recovery. An I/O failure after partial restoration can leave queued metadata uncertain; reconcile the affected record instead of resetting storage. Title, episode and result do not create new authorization.

The native launcher is checked before admission, using the current executable and existing CLI script. On Linux it can reuse the running executable inode through `/proc/<parent-pid>/exe` after a path replacement; an unavailable entry reports `launcher_unavailable` and a restart hint. Explicit custom executors own their invocation.

Independent turns run under session and route capacity. Admission prepares isolated inputs before the receipt and prepares worktrees before launch; agents use the existing tools and dependencies. When no independent work remains, a TUI/RPC caller can end its turn and let results arrive through their normal routes. A ready notice can arrive while other work continues. Ten minutes without child activity emits an inactivity checkpoint with a bounded tool summary when available. Observation or delivery acknowledgment consumes the checkpoint, new child activity re-arms it, and the child stays running until it settles or is stopped.

Persisted read grants are revalidated before accepting another turn and during submission preparation. A changed or missing canonical identity returns `capability_invalidated` without launching another child; later changes still fail closed in native file and typed Git guards. The current native append range can carry an `agents.capability-failure` marker that preserves this classification. Verify the intended roots before invoking a new named agent; keep task-owned temporary inputs available for dependent work.

## Trusted host tools, not an OS sandbox

Managed agents have Pi-compatible `read`, `grep`, `find`, `ls`, `edit`, `write` and `bash` schemas, including image reads. The worker toolkit's operations share a source-to-prepared path mapping and a child-local FIFO, so authorized file edits, commands and tests can use the same bytes. The extension uses existing tools and dependencies; task owners arrange any authorized environment preparation.

Native file tools enforce granted ranges and exclude managed Git metadata. Isolated candidate freeze checks changed paths; apply also checks the resulting merged destinations, including parent-side renames. Bash, configured third-party code, credentials and network access remain subject to task authority and external controls: the toolkit is for trusted host execution, not an OS sandbox.

Bash uses an ordinary POSIX process group, waits for operation cleanup, and terminates its known descendants on cancellation, timeout, or exit. Managed native search processes are also drained on shutdown. Unconfirmed writer cleanup latches failure; a candidate cannot be frozen merely because an assistant said it finished. This is normal process cleanup, not an adversarial containment guarantee. The mandatory native `agents.worker-lifecycle` ready/stopped pair is separate from optional performance markers.

## Read-only Git evidence

Tool availability follows access grants, not role or child identity. A read grant includes search, Git read, and shell. A write grant adds edit and write. The separate `git_read` request chooses `status`, `diff` (`commits`, `index`, or `worktree`), single-file historical `show`, or bounded `log`; it supplies an authorized repository selector and literal owner-relative paths. Commit/ref inputs resolve to exact commit IDs, and `show` returns a blob ID. `git_read` itself exposes no arbitrary argv, shell, checkout, apply, fetch, configuration mutation or additional grant. Separately available host tools remain governed by explicit task authority and the trusted-host boundary.

Git metadata admission permits ordinary repositories and registered linked worktrees, rejects unsupported layouts, external/symlinked object stores, alternates, grafts, config includes, filters, partial clones and worktree-specific configuration, and ignores replacement objects throughout Git phases. Parent symlink traversal is refused; historical symlink blobs are read literally, never followed. External read subdirectories remain narrow grants. External diff/textconv, pagers, hooks, fsmonitor and network protocols are disabled; mutable content-filter/encoding declarations fail closed. These checks are a typed capability boundary in a trusted host, not an adversarial filesystem-race sandbox.

Historical gitlink changes retain short recorded commit deltas without submodule recursion. Mutable queries involving scoped index/HEAD gitlinks are explicitly unsupported rather than inspecting another Git store. Binary or attribute-suppressed patches return incomplete/unsupported evidence. Mutable operations fingerprint scoped source/index/HEAD before and after; detected drift discards output. Equal endpoint fingerprints are not a transactional snapshot or acceptance judgment.

Results have explicit completeness, a 64 KiB UTF-8-safe text limit, bounded paths/inventory/metadata, at most 100 log entries and 2,000 show lines per request; subprocess output is bounded at 1 MiB and each Git process at 30 seconds with cancellation. Git stays in the managed child's process group for owner shutdown. Unavailable or incomplete output must not be represented as a full diff. Delegators supply exact accessible patches/blobs or verified Git query capability, accessible review rules, and current input identity; a continuation alone does not refresh a captured source snapshot.

## Workspace and dependency state

### Shared checkout

Packaged roles use `workspace: "shared"`; an invocation or role definition can choose isolation. Shared writers work directly in the granted Git checkouts, including work alongside existing uncommitted changes. Shared mode creates no private Git input, worktree or candidate. The report and working-tree diff are the acceptance evidence; include untracked files when inspecting the diff. Assign distinct file and resource ownership to overlapping writers, since separate child processes do not share a file-mutation queue.

The child records the first pre-image and last observed content digest for each path its guarded `edit` and `write` tools touch in a turn. A stop with `revert: true` uses the latest turn's record after settlement: restore a regular file's pre-image or remove a newly created file when the current content still matches what the child left. Paths that have since changed, whose prior state was unsupported, or whose restoration fails are kept and reported. Shell writes are unattributed and have no separate rollback record. Review any retained or unattributed changes in the working tree before accepting the result.

### Isolated input

For each isolated writer, a fresh independent index captures visible tracked and non-ignored files, including staged, unstaged and untracked content, while preserving the parent index. Exact-owned refs pin Git trees and internal commits. Each writable repository gets a detached linked worktree with its own index and that repository's shared object database. The logical session spans the prepared roots; access to same-repository read dependencies maps to prepared input and remains read-only. The `.git` file and administrative identity are validated as linked-worktree metadata. Managed Git commands suppress inherited Git configuration, hooks and filters; unsupported source types fail visibly.

Worker input manifests retain Git workspace identity. Dispatch, refresh and commands leave dependencies and ignored environments outside snapshot copying and certification. Project/Git ignore rules determine ordinary source and candidate membership. Workers prepare local environments when the authorized assignment needs them, using existing commands and tool-owned caches. Source-link, Git metadata and candidate ownership checks remain independent.

An isolated agent's later turn reuses the pinned input, including a cancelled queued turn that had not yet checked out that input. Explicit idle refresh performs Git three-way integration and preserves ignored worker-local dependency installations. Candidate freeze discovers additions, deletions, renames, executable modes, binary changes and contained symlinks relative to the fixed input. Keep command outputs and auxiliary files in scratch; failures retain diagnostic evidence.

## Historical usage export

`bun scripts/export-agent-usage.ts --agent-dir /absolute/path/to/agent` previews the one-time accounting export from `subagent-managed-sessions/` and the former `managed-agents/<handle>/native.jsonl` layout. Run it from the source checkout. Stop all writers before an actual cutover, review the dry-run receipt, and add `--write` only for the authorized agent directory. The exporter leaves both sources in place and does not replace a destination. Its duplicate scan reports newline-delimited all-NUL holes in destination files separately: those bytes contain no request identity, and later rows still participate. Other unreadable destination data blocks publication. Review conflicts, partial inputs and missing model attribution separately. Repeating the export does not add a second charge for an existing record.

An export is a usage-only projection under the owning project's `sessions/<project>/agents/`: it retains recorded identities, timestamps, model attribution and usage, without copying prompts, answers, thinking or tool output. A published entry ID combines the original session UUID and native entry ID; `nativeEntryId` preserves the latter verbatim. This prevents readers with source-wide ID deduplication from collapsing independent requests that reused a short ID. Generic Pi readers require a nonempty `cwd`: a usage-only header uses `.` and the containing directory identifies the project. It is for recursive local usage readers, not native continuation, conversation replay or historical collaboration evaluation. An auxiliary request with its own provider and model (for example a cache warm) keeps its own charge. A recorded charge with no model stays in a redacted `agents.usage-unattributed` entry and in the receipt subtotal, separate from model totals. Exit `1` means incomplete or unavailable coverage; even a safe partial export can return it. An export receipt conveys no permission to release Git worktrees, candidates or retained inputs.

## Registry, native continuity, and replay

Pi builds the base system prompt and chooses `APPEND_SYSTEM.md`. The child appends the selected role's Markdown body through the native hook, independently of `inheritSkills`. Pi chooses a trusted project append file in the child source before the agent-directory file. Prompt construction runs per episode; the parent conversation stays in its own session.

`<agent-dir>/managed-agents/` is the private extension directory; `_provenance/` holds the current epoch manifest and lock. New registry, internal cache and managed tool records use collaboration version 5; readers exclude version 4 and older before interpreting task or candidate payloads, and leave the bytes untouched. The retired `agent` tool has no alias. Each internal handle owns a registry, its private resources and optional observations. It binds one native Pi file at `<agent-dir>/sessions/<parent-project>/agents/<Pi-timestamp>_<native-UUID>.jsonl`. The current parent file selects the project bucket when available; otherwise the parent working directory selects it. The native file identifies the child session and preserves the actual execution cwd. Later turns append to that same file. Native Pi IDs and Git object IDs remain opaque. Private storage uses exclusive locks and staged fsync/rename; unknown lock ownership requires coordinated recovery.

There are at most ten open logical records per repository/main session across branches and 256 episodes per record. Release frees an open-record slot. Exact-owned discard removes private working artifacts and preserves registry and native evidence, including any already exported usage prefix. Per-workspace, registry and candidate limits bound individual objects. Native finalization streams bounded JSONL lines and verifies framing, ownership, lineage and post-read stability independently of cumulative native history size. Optional observation reads are bounded separately (including a 32 MiB native-read limit); required-data I/O or integrity failures stay visible.

Roster and name discovery use retained records, not a storage-size inventory or a reclamation pass. Session-scoped names remain reserved across releases and branches. Storage cleanup is explicit; the extension has no idle TTL or automatic reclamation policy.

On Linux, online reconciliation first checks the writer’s machine, boot, PID namespace and process start. A same-boot parent that died during child execution additionally needs an exact launch receipt, an absent child process group and native shutdown evidence for that episode. Only toolkit-owned in-process file operations qualify for this crash proof; shell or opaque tool activity, missing receipts, or an unsettled child leave execution unconfirmed. Pending finalization and uncertain apply preserve their recovery fences.

`stop_agent` asks the engine to reconcile an interrupted agent. Recovery checks settlement evidence without relaunching or applying work. An isolated stopped episode without an applicable candidate can retain registered worktrees and input revisions for scoped inspection. Compare retained edits with those inputs and the current destination before integrating any part. Treat an unavailable comparison as unknown.

Use `release_agent` with `disposition: "discard"` for unneeded private working state. For an old UUID marker or insufficient online settlement evidence, an operator can retire one abandoned episode from the source checkout. Stop all Pi processes, managed children and other writers using that agent directory, confirm they cannot restart during repair, and inspect the owned workspace before declaring quiescence. Run `bun scripts/recover-agent-offline.ts --quiescent-all --agent-directory ABS --repo ABS --session ID --anchor ENTRY --handle HANDLE --episode N` (use `--null-anchor` for a root anchor). Supply the original parent repository, session, creation anchor and exact internal episode. The command backs up the registry and any writer marker or abandoned recovery claim, leaves working files untouched and reports the backup directory. On a partial error inspect that backup and current files before retrying. Resume in the original session, check the agent by name and decide what to keep. A full reset requires separate authority and coordination with all affected owners; version exclusion preserves prior records in place.

Each episode starts a native Pi print/JSON process with the same native file and workspace bindings. The logical agent remains addressable while idle; the child process exits after the turn and a later message reopens its native history. The session-owned supervisor can outlive a submission tool call, without an implicit task-lifetime deadline. Pi owns compaction, tree/fork behavior and appends. Native readers validate the physical append range and accept legal ancillary entries; malformed framing, IDs, lineage and cwd fail visibly. Authoritative final-message, executed-tool and settlement signals determine completion; redundant `agent_end` aggregates and unexecuted proposals do not replace them. Actually started tools fence completion. Changed leaf, unknown request outcome and interrupted writers retain their recovery fences.

At acceptance, the role's effective `inheritSkills` boolean is stored on the queued record and used for that episode even if configuration changes before launch; later accepted episodes resolve again. The already-loaded effective parent Skill catalog owns native exclusions and precedence only for its own source repository. Every other prepared repository discovers its own applicable project catalog, even when it contains the origin as a nested checkout; neither primary-root selections nor primary-root suppression silently replace another root's catalog. Only selected project Skill paths that belong to the captured Git input are retained privately across continuation, even if a later parent resource reload removes the original files; explicit refresh recaptures that selection. Ignored private project guidance instead follows the current effective parent catalog on each episode and is never treated as snapshot membership. Their paths are remapped to the captured source, and only selected canonical Skill file/directory paths go through CLI. Direct service callers without a parent catalog use Pi's public non-installing Skill parser with project-before-user fallback and cannot infer package-specific enabled resources. Captured repository Skill membership and bytes take precedence over mutable parent source, while ignored private and user-installed guidance is read at its owner. Actual Skill bodies/references remain on-demand reads behind a separate read-only guidance grant pinned to selected physical owners. Native context discovery remains active independently of this switch; original-project ancestors precede the child snapshot's selected repository override, while managed-storage ancestors are omitted. User-installed and trusted private resources outside the captured Git input can change between episodes. The guidance copier does not copy parent conversation history, credentials or arbitrary read-evidence project settings. The native host and explicit access determine the eligible configured tool catalog; role or child identity alone does not remove otherwise eligible operations. The worker kit claims a builtin name only after configured `session_start` registrations have finished, so an ordinary same-name override registered there keeps its implementation and schema. Host-side guidance discovery never provisions a package; the unchanged Pi subprocess still follows its own configured startup package/offline policy. This is a trusted-host guard, not an OS sandbox or shell network policy.

The engine replays committed terminal evidence without another launch, charge or current route lookup. Its bounded request telemetry records owner/invocation identity, start/duration, admitted work, launches, replays and observed extension/configuration epochs. Each episode retains original execution provenance, route and effective `inheritSkills`. Replay describes the historical episode; use `list_agents` for current state. Unknown outcomes need reconciliation. Native validation, candidate freeze when applicable and required result save are separate finalization stages. A failure preserves recorded child output, usage and execution status while making the overall result failed and non-applicable. An owned pending marker protects the final registry commit; uncertain persisted state stays non-actionable. Missing timing remains unavailable. Successful non-retrying compaction may retain a valid report when fresh settlement and closed activity establish it.

The next interactive or RPC prompt that starts a user turn after interruption or resume can receive one bounded hint from current-branch and live evidence. Use `list_agents` to read current state and named reports, then `stop_agent` to confirm interrupted work has stopped. The main agent interprets the new request, preserves useful work, and releases obsolete work after review. Steering or follow-up within a running request does not trigger discovery. Recovery checks project trust and active tools, and uses native history as authority. The hint neither resumes work nor starts a turn; ordinary requests keep their stable prefix.

## Candidates and recovery

For an isolated agent, unapplied candidates from successive turns compare against the same pinned base. Apply integrates into the checkout and leaves that base unchanged. Use `agent_candidate` with `action: "refresh"` before starting another turn that needs updated checkout files. Successful refresh establishes a new base and invalidates the previous candidate. A successful complete report with no changes produces none.

The hub tracks the latest episode it considers shown to each caller. Roster, wait and result delivery can advance that mark. When a candidate operation sees a newer episode than the caller's mark, it returns that result and leaves the checkout untouched. A peer's observation does not advance the main agent's own mark. Read the named report before applying. The engine rechecks exact internal episode and candidate identities before mutation.

On apply or refresh conflict, the tool reports the operation failure and any available bounded sample of changed paths per root. These paths describe the change scope, not a list of proven conflicts. The engine retains per-root progress and recovery evidence. Resolve the conflict within authorized scope before another mutation.

Freeze creates immutable Git candidate objects and validates source identity, changed paths, environment and byte limits. Apply uses Git three-way merge against a fresh capture of the current parent worktree. Compatible parent edits and renames are preserved, conflicting content is not overwritten, and the parent index is unchanged. Candidate paths remain immutable and root-qualified in aggregate projections; each root retains Git-relative paths. Apply records its actual integration footprint, including allowed renamed destinations or an empty no-op footprint. The whole bundle's target and candidate identities are checked under the destination locks before any target write. A clean per-root pre/post integration journal is retained before mutation; conflict results are not executable journals.

Application proceeds per root under destination locks; disjoint destinations may progress concurrently. An uncertain failure marks apply unknown, and `applying`, `partial` or `unknown` blocks continuation pending reconciliation. Already integrated roots retain their progress, and the engine rechecks recovery fences on the freshly locked record. Reapplying an applied candidate returns its historical outcome without writing again; verify current checkout bytes independently.

`release_agent` with `retain` preserves working state and evidence. `discard` removes exact-owned working artifacts and preserves closed registry/native history, applied checkout changes and any exported usage prefix. Missing worktrees do not erase the remaining ref inventory; incomplete release stays visible and retryable. A successful report, settled process, frozen candidate or successful apply is evidence for the main agent's acceptance judgment.

## Coordination telemetry

The main session hub appends Pi custom telemetry entries of version 1 with `atMs` and the fields below. Sender, recipient, initiator and operator are `{ kind: "main" }` or `{ kind: "agent", name, role }`. These telemetry entries carry no message body, prompt or report; Pi records delivered conversational messages separately.

| Entry | Evidence |
| --- | --- |
| `agents.message` | `from`, `to`, UTF-8 `bytes`, `kind` (`message` or `receipt`), `delivery` (`running`, `started-turn`, `queued`, `held` or `main`) and `startedTurn`. |
| `agents.turn` | `phase` (`started` or `finished`), `name`, `handle`, `role`, `episode`, `workspace` (`shared`, `isolated` or `none` for read-only), effective `may` and `initiator`. Finished turns add available `status` and shared-writer evidence: bounded root-relative `writtenPaths` (up to 64), `writtenPathsTruncated`, `shellUnattributed` and `changedPathCount` on a non-success result when attribution is available (null when shell use leaves the count unknown). |
| `agents.stop` | For a shared-writer stop with revert: `name`, `handle`, `by`, counts `reverted` and `kept`, and `unknown` when shell work leaves attribution incomplete. |

Telemetry is optional evidence: a write failure does not fail coordination, and missing attribution is not a known zero.

## Observation and consumers

Public event hooks record client-observed assistant, streamed thinking, local-tool, delegation-wait, and compaction spans. Each main run (Pi's session-level run from `before_agent_start` through `agent_settled`) uses an opaque process clock and origin. Missing, backward, nonfinite, duplicate, or unclosed endpoints remain incomplete. Final thinking blocks without streamed endpoints do not become complete zero reasoning. Ordinary parent turns, idle shutdown, and inactive delegation tools write no parent observation. Hooks own no timer, UI slot, dispatch, provider payload, or model configuration.

Native v1 observations contain direct assistant/compaction/branch-summary usage, owner/entry identities, configured child tools/context window/capability hash, and scalar command endpoints/status. The current markers copy neither command text nor prompts. A failed summary without usage is unknown, not free. A structurally valid owned native range can retain usage, commands, and capabilities without a terminal timing marker; missing timing stays unavailable rather than erasing the other planes or inventing zero duration. Partial physical tails, owner/leaf drift, and unreadable ranges still fail closed. Retained usage describes committed recorded rows, not an assurance that a forcibly stopped in-flight provider request has a complete bill. Configured tool evidence is host state, not the final provider payload after later handlers. Usage remains Pi/provider-reported; there is no pricing estimator, server-utilization inference, or provider-quota estimate.

Worker command markers use version-two domain-separated hash keys for nonempty host tool-call IDs bounded to 4 KiB UTF-8. Host IDs are not validated as managed handles. Current observation projections declare `commandCorrelationVersion: 2`; command correlation is an internal attribution field, not a second model-facing session identity. Duplicate, unknown-version, or unmatched markers retain partial command coverage. There is no default command timeout or cumulative command-count/output execution budget. Explicit command timeouts and cancellation remain; bounded command markers and output projections do not terminate otherwise healthy execution.

Optional observation sidecars are bounded to 64 KiB per episode and are not part of the required registry, request, or terminal ACK. No aggregate storage advisory reclaims sidecars. Missing/corrupt caches hydrate as unavailable; an optional write failure cannot invalidate a candidate or committed result. Native history, source integrity, required lifecycle evidence, and candidate failures are never waived as telemetry failures.

The evaluator's `observations` section consumes owned physical parent windows and child projections, deduplicating native owner/entry and logical handle/episode identities. Copied fork prefixes, nested aggregates, replay, inspect, and repeated reads do not create new usage. Prior valid episode evidence survives a missing cache on reread; conflicting stable evidence fails closed. Parent usage and child usage are separate. Cross-run worker union requires matching clocks/origins; child reasoning/tool/compaction summaries sum per-episode measurements as effort, never an unrelated-clock union. Unattributed wall gaps are not asserted user idle.

Evaluation selects an explicitly supported collaboration version before interpreting nested payloads and separates unsupported, malformed and unavailable evidence. Admission and owner-tagged terminal events are distinct; terminal events own launch and execution timing. Replay, roster reads, waits and repeated root transitions do not duplicate native usage or logical candidate counts. Per-root integration/recovery/release facts stay separate from launch and candidate counts. Epoch matching uses recorded revisions. Explicit offline disposition stays separate from recorded execution and integration. See [Local Development](../../README.md#local-development) for the maintained evaluator's evidence scope.

Agent tool text uses names and presents bounded reports, receipt status and operation errors. Tool details hold engine correlation data for observers. The retained registry keeps per-root application, recovery and release separate; the read-only UI exposes available details. Model-readable reports include recorded provider/model/thinking when available. A stored running record alone does not establish live activity.

Terminal facts are persisted before publication to [Notices](notices.md). The executor emits admission, live and terminal facts with observation disposition; the Notices consumer owns main execution-result delivery. Queueing a notice is separate from observation. Suppression, a blocked delivery, or a peer-initiated turn leaves source evidence available through explicit list. Terminal results leave Tasklist unchanged. Foreground observation or a wait releases the model on its own boundary; asynchronous TUI activity comes from bounded observer snapshots, not updates to a settled tool call.

The TUI observer publishes bounded assignment headlines and available live call identity, redacted target, start/activity/output times, status, reported timeout and output tail. Missing fields stay unknown; the observer never reconstructs activity from a raw transcript scan. The separate session query enumerates retained same-owner and labeled off-branch records, including closed history, with deduplicated usage and explicit incomplete/unavailable coverage. History invalidates on lifecycle changes, independent of heartbeats and paging. See [Agents UI](agents-ui.md) and the independent [usage lanes](usage-metrics.md).

## Accounting boundary

Pi adds nested work to footer, `/session` and RPC totals when a tool returns top-level `usage`. The agent tools leave usage in separate native, observer and evaluation records; provider-side billing still applies. Count each recorded child request once and keep missing usage unknown.

## Verification and removal

Deterministic tests cover repository identity, linked worktrees, pinned inputs, replay, writer settlement, immutable candidate application, concurrent refresh and partial release. `tests/agents-peer-host.test.ts` uses a real RPC-mode Pi host with synthetic model responses and native child processes. It exercises running-message delivery, waking an idle child and using a granted tool again, peer-led review and result routing, sibling control refusals, two shared writers beside uncommitted work, stop/revert, the per-caller isolated apply guard, a user-defined route and the custom-message path to main. These are offline behavior checks; live-provider decisions, billing and semantic acceptance need separate evidence.
