# Test-suite evidence lanes

This is an inventory and execution contract for the source checkout, not a claim about a published package or model behavior. The source test manifest in `scripts/run-test-lane.ts` classifies every discovered `tests/*.test.ts` entry exactly once; an unclassified new file fails lane execution instead of silently entering or leaving a gate. Family rows below expand when an entry has a different dependency or disposition. Assertions within retained mixed suites have not been certified as individually independent merely because the suite passes.

## Baseline (2026-09-23, before lane changes)

`bun run check`: exit 0 in 168 s, typecheck and shell syntax passed; Bun reported 625 pass, 0 fail across 85 files in 147.34 s. No `(skip)` appeared in the output; the conditional skip sites are still environment-dependent. `bun run e2e:installed-offline`: exit 0 in 5 s, JSON `result=pass`, `source=installed`, `fixture=synthetic-workflow`, tool/source identity 1, extension-off tool 0, co-load 1, synthetic snapshots 1. The first attempted timing wrapper was unavailable (`/usr/bin/time`), so these timings use Bash `SECONDS`; that failed wrapper did not run a test. Neither command invoked a live model. These receipts apply only to the baseline worktree, which already had unrelated, uncommitted test-strategy edits; they do not verify the final candidate.

## Entry inventory and dispositions

An independent expectation means a contract, schema, specified transition, protocol response, or synthetic fixture assertion separate from the act of running the test. `keep` below retains the existing oracle; it does not certify every assertion in the family. Cost is approximate (`low`, `medium`, `high`); per-test durations depend on the host. Source owners diagnose their respective extension family; package/fixture owners diagnose harness and script failures. `fast` has no required external host or service; `isolated` may use disposable filesystem, Git, and subprocesses; `host` needs an installed local executable. All three classes remain in the source `check` aggregate. Explicit offline, UI and snapshot commands provide additional evidence where applicable.

The lane manifest is the exhaustive file-level membership map; an unknown entry or overlapping membership is an error. Explicit shell probes and the `.e2e.ts` entry are outside the 85-file glob and remain separately listed. Actual conditional skips must be read from the command output for each run. No assertion has been deleted on the strength of this inventory alone.

## Commands and acceptance boundaries

- `bun run test:fast`: local source logic/schema/component tests; no installed executable required. `bun run test:isolated`: disposable filesystem/Git/subprocess and shim-script tests; no live provider. `bun run test:host-optional`: existing installed-Pi/CC/PTy tests, conditional skip for ordinary source feedback. `bun run check` runs typecheck, all three source groups and shell syntax; it preserves the old `tests/*.test.ts` membership. `bun run test` remains the original full-glob entry.
- `bun run e2e:installed-offline`: **required when installed workflow/co-load behavior changes**, real installed Pi, synthetic provider and source checkout by default. It fails if prerequisites are missing. `bun run e2e:host-offline` also requires installed Pi and runs the host tests; source tests' internal optional skip must not count as host acceptance, so the command checks the executable first. This does not assert a global CI requirement for unrelated source edits.
- `bun run e2e:ui-offline`: required for affected fullscreen/PTY behavior, with local `pi`, `cc` and util-linux `script` prerequisites checked before the affected tests; `bun run e2e:subagents-ui` remains a separate observer click check. A scope that does not change that UI can report it as not applicable rather than claiming UI verified. Required commands must fail or report unavailable, never count an optional skip as a pass.
- A real **installed snapshot** check must pass the actual snapshot root to `bash scripts/run-installed-workflow-probe.sh /path/to/snapshot` after an independently authorized installation. Running the default source-root command does not prove snapshot deployment. No snapshot installation or live provider evaluation is part of this change.

When a source test moves between feedback groups, the manifest and `check` coverage must both stay complete. A changed shim assertion may only claim shell-runner behavior; a real Pi result is needed for co-load/state claims. Clean disposable test directories and subprocesses on both success and failure; avoid retaining credentials or full prompt/session dumps as evidence.
