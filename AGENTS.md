# AGENTS.md

## Project

This repository is the authored source for small local Pi extensions. Extensions may change the host loop's active tools, prompt context, editor completion behavior, provider request payload, or execute bounded session-owned delegation, but must not replace the coding agent with a second lifecycle engine.

The package exposes nine maintained extensions: `multi-skill-mentions` as an explicit prompt expansion mechanism, `fast-gpt` as a branch-local request profile, `subagents` as a bounded session-owned asynchronous managed-delegation executor, `subagents-ui` as a default-loaded TUI-only read-only observer, `status-footer` as a TUI-only compact status footer, `work-timing` as TUI-only timing feedback, `workflow` as a branch-local task list and focus aid, `agent-bark` as a main-agent-only adapter to the optional user-owned notification hook, and `retained-shell` as the TUI/RPC retained bash execution path. Keep each extension's behavior, state, tests, and removal semantics independent.

## Layout

- `extensions/multi-skill-mentions/`: TUI completion and input expansion for loaded skills
- `extensions/fast-gpt/`: branch-local OpenAI Responses service-tier request profile
- `extensions/subagents/`: fixed roles, routes, shared session capacity, managed native/Git-worktree continuity, explicit candidates, bounded observations, and the managed observer-event publisher
- `extensions/subagents-ui/`: default-loaded TUI-only read-only observer overlay; widget, keyed footer status, and completion entries remain off unless explicitly enabled
- `extensions/status-footer/`: TUI one-line footer with model/thinking, optional fast-gpt lightning, original workdir, session UUID, usage stats, context fill, and MCP counts
- `extensions/workflow/`: Pi-owned task tracking, explicit task states, current-context projection, bounded settlement reminders, schema-v5 session snapshots, recovery and an optional TUI view; no dependency on a Skills collection
- `extensions/work-timing/`: live request and reasoning timing with durable TUI-only completion entries
- `extensions/agent-bark.ts`: main-agent notification adapter; child-marker exclusion and parent custom-run filtering stay here, while shared hook configuration and delivery remain user-owned
- `extensions/retained-shell/`: TUI/RPC retained bash execution, bounded output, finite deadline, and inspect/wait/renew/cancel separate from that execution
- `config/csheng-subagents.json`: packaged role routes, semantic-profile mappings, and concurrency defaults
- `.agents/skills/evaluate-subagent-runs/`: maintainer-only read-only evaluator, excluded from the npm package
- `.agents/skills/evaluate-session-cost/`: maintainer-only read-only session cost and prompt-cache evaluator, excluded from the npm package
- `tests/`: deterministic, fake-Pi, subprocess, filesystem, evaluator, and disposable-Git tests
- `scripts/`: redacted temporary-load, installed-package, and explicitly gated live E2E probes, plus the local package snapshot publisher
- `mise.toml`: `publish-local-package` task for the local Pi package snapshot
- `docs/architecture/`: stable product and maintenance truth
- `$AGENT_ARCHITECTURE_DIR/docs/`: shared boundaries, new designs/plans (including single-product changes), retained evaluation results and integration observations; never runtime input
- `mise.toml`: source roots `AGENT_ARCHITECTURE_DIR`, `AGENT_SKILLS_DIR`, `PI_EXTENSIONS_DIR` plus `TMPDIR`; consumers use these resolved values without guessing checkout layout. Retained runtime and temporary artifacts belong under `$TMPDIR/extensions/`.
- Use the project environment and supported entrypoints described in `README.md#project-environment`; `mise.toml` owns ordinary development context without making personal global configuration a product prerequisite. Re-establish target context when crossing projects and preserve caller-owned run isolation; do not duplicate environment values in this file.
- Product protocols and independent check/install behavior remain here; no architecture checkout is required at runtime

## Local Package Snapshot

This checkout is authored source. Daily Pi must load a copied local Pi package, not this working tree and not `~/.pi/agent/extensions/`.

- Pi `packages` local paths load a directory without copying. Pointing user settings at this checkout applies dirty edits on every new process or reload.
- `~/.pi/agent/extensions/` is auto-discovery for loose `*.ts` files and `*/index.ts` trees. It is not this package's install location. `rsync --delete` there would remove unrelated files, and subagents resolves packaged routes as `../../config/csheng-subagents.json` from the extension file, so an extensions-only dump breaks the package baseline.
- Publish with `mise run publish-local-package`. The task runs `scripts/publish-local-package.sh` and rsyncs `package.json`, `config/`, and `extensions/` into `${PI_CODING_AGENT_DIR:-$HOME/.pi/agent}/packages/csheng-pi-extensions`.
- The publisher is bash plus a mise task because the copy is short linear rsync orchestration, this repository already owns bash probes, and mise is the local task runner. It does not edit `settings.json`, the user route overlay, provider/model settings, or `~/.pi/agent/extensions/`, and it does not npm-publish.
- One-time switch: `pi remove` this checkout path from user packages, then `pi install` the snapshot directory. Later publishes only refresh the snapshot; restart Pi to load it. `pi update --extensions` does not update local-path packages.
- Temporary-load probes keep binding to this checkout. Installed-host probes use a disposable settings file that also points at this checkout; they do not publish the snapshot. Live `--installed` E2E uses the real globally installed package.

## Boundaries

- Pi's public extension API, active tool set, model context and registry, project trust, session events, and startup flags are runtime inputs.
- The host Pi loop remains authoritative for parent model turns, tool execution, persistence, user interaction, and final responses.
- The retained-shell extension may replace builtin `bash` only in TUI/RPC when no other extension has registered that name. It keeps one execution identity, bounded output, a finite deadline, and separate inspect, wait, renew, and cancel operations. Print/JSON and managed child tools keep the native draining shell. It must not seize another shell owner or report an unknown exit as 0. A TUI/RPC terminal that the tool call does not return is delivered once through the shared wake reservation; print/JSON and an unclaimed owner do not wake. See [Retained shell](docs/architecture/retained-shell.md).
- The fast-gpt extension may toggle branch-local official OpenAI and OpenAI-Codex Responses requests between top-level `service_tier: priority` and explicit `default`. Until the first `/fast-gpt` command, and for unsupported provider/API/model correlations, requests remain unchanged. Its keyed TUI status is a warning-colored ⚡ when priority is requested on a supported model. Pi and the provider remain authoritative for usage and cost; the extension owns no model alias, provider override, pricing parser, live call, or workflow.
- The status-footer extension may replace the TUI footer with a compact status that renders as one line on wide terminals and wraps field by field when the single line would not fit — each field flows onto the next row only when it no longer fits the remaining whitespace, adding rows rather than dropping fields: model and thinking, an optional warning-colored ⚡ after thinking when Pi's keyed `fast-gpt` status is present, optional `(provider sub)` when the active model is on a subscription, the session's original workdir with the Pi-provided git branch, the full session UUID, session-cumulative ↑ input, ↓ output, R cache-read, optional W cache-write, latest-prompt CH hit rate, cost, current context fill, and `MCP enabled/all` from the mcp-adapter status bus. It must keep the UUID visible when width is tight even after wrapping, truncating a row only when a lone segment cannot fit, omit generic extension-status chrome, remain inactive in RPC, JSON, and print modes, and must not persist session metadata. It reads the branch and keyed statuses from Pi's footer data provider without importing `fast-gpt`, spawning Git, or resolving worktree layout, and does not own Git state or chrome, working-message timing, provider billing truth, or the request-profile selection.
- The work-timing extension owns only the TUI working row and one context-free completion entry after `agent_settled`; it never judges business completion or controls execution. Preserve the metric, rendering and compatibility contracts in [Work-timing metrics](docs/architecture/work-timing.md): thinking R/ΣR and decode tok/s are different windows, footer R has a separate token meaning, and TTFT is not part of the rate. Keep one working-line formatter/writer, TUI-only activation and interval cleanup. Do not change another extension's settings or patch Pi UI methods to claim the row; co-loaded CC working-message configuration is user-owned. Use the existing timing and installed-host TUI tests only for behavior they cover, not as an automatic full-suite requirement for documentation edits.
- The subagent extension may validate and execute hard-bounded session-owned in-memory task batches with optional parent-supplied predecessor edges. Current TUI/RPC submissions default asynchronous; one-shot hosts default foreground and explicit foreground/join remains available. Accepted receipts are not completed execution. Shared global/role capacity and explicit locks span submissions; task-local mutation and destination-resource apply coordination remain separate. Terminal facts persist before event/wake, and a pending wake coalesces until public context consumption. Ordinary delegation stays flat; semantic hard-edge eligibility remains parent-owned. The extension owns physical child routing, readiness, concurrency, locks, cancellation, path capabilities, managed native/source continuity and candidate apply, bounded observations, opaque effective-revision provenance, and TUI observer-event publication. After the applicable host trust checks, a task uses `access` rules with one absolute-path scalar/list `scope` and independent read/write permission; write includes read. One session may write every granted Git root and read other Git or non-Git evidence. Legacy `scope`, `repository`, `writePaths`, and `externalReadRoots` fields are rejected. It does not load another repository's project resources merely because a grant names that path, and it does not read Pi trust storage. Managed records retain bounded owner/branch identity, native/source state, request replay, and candidate facts, not a semantic mission. Candidates are never auto-applied or auto-converged. File-dependent successors require explicit parent apply between dispatches; dependency edges pass reports, not candidate files. The package index does not register historical one-shot `csheng_subagents`, `/subagents-debug`, or snapshot UI v1. The extension owns no semantic lifecycle, approval, verification judgment, review adjudication, repair/continuation decision, automatic recovery, or durable orchestration. Task-targeted cancellation during worker candidate freeze returns too-late; run cancellation stops cancellable work and lets an entered critical section finish.
- Managed workers use trusted host native file/search/bash tools in detached linked Git worktrees with separate indexes. Dependencies are not copied, traversed, hashed or certified; Git/project ignore rules own source/candidate inclusion, and workers prepare local environments only when their authorized task needs them. Admission captures and pins dirty/staged/untracked input without changing the parent index. Continue reuses fixed input; only explicit idle refresh changes it. Immutable input-relative Git candidates integrate by three-way merge into the parent worktree, never its index; apply does not refresh task input. Actual applied paths may differ from candidate paths after a parent rename or no-op merge. Unsupported older records are identified and left untouched. File guards and candidate inventories are not OS restrictions on bash, credentials, network, or hostile process escape. Write grants are prepared as isolated worktrees and frozen only for the selected paths. There is no extension-owned sandbox/container or provisioning. Unknown writer cleanup, source/candidate drift, partial apply, and native-owner/leaf mismatch fail visibly and are reconciled per root before another mutation. Optional observation failures never weaken mandatory lifecycle/source/candidate evidence. Close releases open-record slots, not all retained history; discard keeps native/registry evidence. Normal actions and replay do not perform aggregate managed-root storage estimates or generate storage warnings; historical warning fields remain readable. No automatic cache reclamation or storage reset is provided. Source/candidate, bounded-line decoding and integrity limits remain enforced; cumulative native-history size/count does not block finalization. No implicit runner lifetime, command-count or cumulative command/output execution budget exists. Explicit timeouts, cancellation and process teardown remain; bounded observations may be unavailable independently of execution. A full storage reset requires stopping all users of the agent directory and deliberately abandoning retained histories, candidates and replay records.
- The default-loaded subagents-ui is a TUI-only read-only session inspector; see `docs/architecture/subagents-ui.md`. `/subagents-ui` and `Ctrl+Alt+F` toggle pinned fresh live rows above Enter-expanded paged retained history. Preserve complete current-version history reachability, unchanged session IDs with separate episodes, labeled off-branch read visibility, independent mutation authority and honest incomplete/unavailable recorded usage. Core-owned versioned session-view queries read retained registries/observations without reconciliation or raw-native fallback; current observer snapshots supply live evidence, never complete history totals; unsupported versions are excluded before interpreting their payloads. Heartbeats/repaint must not rescan history, and stale replies must not cross owners. Keep viewport overflow explicit, close-chip/keyboard behavior covered by real PTY checks, and optional status/widget/completion entries off by default. The UI must not call `setWorkingMessage` or `setFooter`, run in headless modes, emit cancellation, or own scheduling/final outcomes; `status-footer` and `work-timing` remain independent.
- The workflow extension provides one branch-local task list through `csheng_workflow`: `set`, `update`, `inspect`, `pause`, `resume` and `cancel`. The main agent owns the goal, decomposition, verification and completion judgment. Task states record that judgment; the extension adds no requirements, attempts, evidence receipts or separate delivery acceptance. It works without this Skills collection and does not discover or enforce Skills.
- Task IDs identify revisable work items with `todo`, `doing`, `blocked`, `done` or `cancelled` status and optional notes. Blocked items describe their actual blocker. Batch changes persist atomically; cancellation remains distinct from successful completion. Tracking failures do not require repeating completed business operations, and task tracking never grants write or delivery authority.
- Pi retains the loop. Current task context and bounded reminders help the agent retain focus; a reminder does not add checks or review. Only active actionable work can receive a settlement follow-up, with one reminder for unchanged task state until a real update or user input. Trust, queued input, abort/error, session ownership and an already reserved completion/attention wake fence dispatch; pending managed work is context, not a global reminder veto. Subagent results never automatically complete tasks.
- Persist schema-v5 task snapshots in Pi session history. Recovered unfinished work is visible and paused until explicit resume. Unsupported older completion-contract state is ignored with a diagnostic and can be replaced with a new list; do not migrate acceptance or rewrite history. `/workflow-ui` retains its read-only show/hide/list behavior, done titles are struck through and cancelled work stays distinct. Headless modes mount no UI. The owned protocol is described in `docs/architecture/workflow.md`; offline checks do not establish live-model effectiveness.
- Pi's native resource loader remains authoritative for effective Skill discovery and context-file precedence. Managed children receive applicable global/project Skill catalog paths by default through the existing subprocess and a narrow read-only guidance grant; `roles.<role>.inheritSkills: false` disables the automatic catalog for that role, not context files or prior native history. Original project ancestors and captured source context are mapped without importing external read-root projects or ordinary extensions/MCP. The package does not independently parse, execute, or enforce Skill instructions, and guidance never expands role tools or write authority.
- Child roles are code-owned and fixed. The repository ships tested role-preferred peer routes and optional semantic profile mappings; a user-owned Pi-agent-directory overlay may change persistent defaults. Project repositories cannot provide routes, and the package never changes the parent model or provider settings.
- A task may provide fixed provider-neutral execution and thinking profiles. When the user explicitly selects a concrete model or Pi thinking level, the parent may also pass ephemeral task `model` and `thinking` overrides for any role. Those fields override default selection without mutating package or user route configuration. The parent owns semantic projection; the extension never reads a plan or Skill.
- Invalid route configuration, project distrust, unsafe graphs, path escape, writable isolation failure, child failure, and candidate drift fail visibly without widening authority.

## Working Rules

- Keep each extension small and independently reversible.
- Persist only the minimum state needed to restore host behavior. Scheduling and active control remain session-owned and memory-only; an asynchronous submission never becomes a cross-session mission. Managed native/source, replay, and candidate state persists only for explicit same-task actions. Historical one-shot workspaces were temporary diagnostic resources and are not a current runtime tool. Private JSONL remains evidence, never automatic orchestration or semantic resume state. The provenance manifest stores only the current opaque extension and configuration pair.
- Preserve ordinary Pi behavior outside each selected profile or explicit tool call and when an extension is disabled.
- Bound child prompts, capability files, observer snapshots, process output, diagnostic storage and individual workflow operations against their actual resource risks; workflow task history follows its documented persistence rules. Clean temporary resources on success, failure, timeout, abort, and session shutdown while retaining launched-child diagnostic sessions under their explicit retention policy.
- Keep probe and evaluator output redacted. Never print raw user settings, route files, model selectors, prompts, task IDs, credentials, environment values, session paths, or external file content.
- Treat package and user route files as read-only persistent defaults. Never create, edit, or delete either file to satisfy one dispatch; explicit task route failure is typed and has no fallback or retry.
- Do not add dynamic roles, background missions, durable orchestration ledgers, hidden model fallback, automatic retry, or a Skill-specific runtime contract without a separately approved design. Purpose labels and child identity do not impose a blanket tool ceiling; explicit read-only intent, scoped access, supported host capability and real resource ownership remain binding. Trusted shell execution is not an OS sandbox. The workflow extension's branch-local session snapshots are the approved ledger exception: they carry no scheduler, background execution, or automatic recovery.
- Do not commit, push, npm-publish, deploy, create a remote, install packages globally, create a user route file, or change provider/model settings without explicit authority. The local snapshot publisher is `mise run publish-local-package` and still requires that explicit authority; it must not rewrite Pi settings.

## Validation

The current managed runtime integrates `git-workspace.ts` and `session-supervisor.ts`. Stable contracts live in `docs/architecture/subagent-execution.md`; dated implementation and verification records are routed through the shared coordination index. Offline synthetic host/native-child validation is not live-provider effectiveness or deployment evidence. Workflow observes pending owned execution to avoid redundant reminders, without polling or interpreting transport success as task completion. It adds no acceptance protocol to subagent execution.

Use Bun 1.4.2, declared in `packageManager`, for dependency installation, TypeScript checking, tests, repository-owned e2e/probe scripts, and maintainer evaluators. Install from the tracked `bun.lock` with lifecycle scripts disabled by `bunfig.toml` and the explicit command below. The deterministic test glob excludes deliberate e2e entrypoints and uses a 120-second default per-test timeout. Keep actual installed `pi` invocations and its runtime unchanged; do not replace Pi-owned `npm:` sources or `~/.pi/agent/npm/` paths with Bun-specific names. Preserve filesystem-order path regression coverage with independent fixture targets rather than deriving expected identities from raw-path `realpath`.

Choose verification from the changed behavior. Workers use relevant unit tests, compilation or a narrow reproduction for local feedback, and return actual results and uncovered behavior. The main task owns integration, conflict resolution, E2E and full-suite selection, and final acceptance; it may delegate a specific check without duplicating verification ownership. Reuse still-applicable worker evidence. Documentation or prompt-only changes may need inspection and applicable structural checks, not a new test over wording or an automatic full suite.

Use the existing dependency environment; install from the lockfile only when dependencies need preparation. Available commands are entrypoints, not a checklist to run after every change:

```bash
bun install --frozen-lockfile --ignore-scripts
bun run typecheck
bun test ./tests/<affected-suite>.test.ts
bun run check
bash scripts/run-temporary-subagents-probe.sh
bash scripts/run-installed-subagents-probe.sh
bash scripts/run-temporary-workflow-probe.sh
bash scripts/run-installed-workflow-probe.sh
```

`bun run typecheck` and the affected test files provide local feedback. The main task selects `bun run check` for broad executable impact, an explicit delivery requirement or uncertainty that focused checks cannot resolve. Run the temporary/installed subagent or workflow probes only for the affected loading and host boundary; their presence here does not require all four on unrelated edits. A repair invalidates the evidence for the affected behavior, not every earlier check.

`bun run check` now runs `test:fast`, `test:isolated` and `test:host-optional` after typecheck, covering the same source test files as the original glob; `bun run test` remains the full-glob entry. Inventory drift fails the split lanes rather than silently omitting a new test. The optional host group may skip when Pi, CC or PTY support is absent; it does not satisfy required host acceptance. Run `bun run e2e:host-offline` for affected installed-Pi behavior and `bun run e2e:ui-offline` for affected fullscreen/PTY behavior; these require their host prerequisites and reject skipped required tests. See `docs/test-suite-evidence-lanes.md` for costs, boundaries and failure owners. The `installed-*-probe.test.ts` suites use shim Pi and only prove runner behavior.

For changes to installed workflow/co-load behavior, `bun run e2e:installed-offline` is the explicit acceptance lane: it invokes the real installed Pi with a disposable agent directory and synthetic provider, checks tool registration, extension-off behavior, co-load, and a persisted workflow snapshot, then emits a bounded JSON result with fixture identity. It fails rather than skipping when Pi or another prerequisite is absent; run it only in an environment that provides them. The normal `bun run check` does not require installed Pi. This lane does not prove live-model instruction following. Keep focused rule/contract tests for independently specified behavior, not prompt-wording snapshots or version strings copied from docs.

The multi-skill mention probes use Pi print mode and cross model/provider preflight. `PI_OFFLINE=1` does not disable inference, so these probes require explicit provider-call authority and do not belong to the deterministic offline lane:

```bash
bash scripts/run-temporary-multi-skill-mentions-probe.sh
bash scripts/run-installed-multi-skill-mentions-probe.sh
```

The delegation probe lane is a measurement lane, not a gate: it runs headless `pi` against a throwaway project and a mock subagent tool to measure whether the parent model calls the tool under a selected shape, with capability-only guidance by default. Its opt-in balanced/aggressive treatments are historical fixture text, not production defaults or supported route settings. It spends provider capacity, always includes control prompts, prints Wilson intervals with the frozen prompt-set fingerprint, and writes one JSON artifact; use `--dry-run` to inspect the plan first. Keep its dated conclusion in `$AGENT_ARCHITECTURE_DIR/docs/evaluations/pi-integration/` and its raw JSON artifact under `$TMPDIR/extensions/`, and never add it to `bun run test`:

```bash
CSHENG_SUBAGENTS_DELEGATION_PROBE=1 bun scripts/run-delegation-probe.ts --dry-run
CSHENG_SUBAGENTS_DELEGATION_PROBE=1 bun scripts/run-delegation-probe.ts --guidance aggressive,off --trials 6
```

The live subagent provider lane is separately authorized and never belongs to `bun run test`. Parent owns acceptance of that lane; these instructions do not treat it as verified package co-load:

```bash
CSHENG_SUBAGENTS_LIVE_E2E=1 bun run e2e:subagents
CSHENG_SUBAGENTS_LIVE_E2E=1 bun run e2e:subagents --installed
```

The installed-host observer click check is also deliberate and never belongs to `bun run test`; it resolves the installed `pi` binary and skips when that binary or util-linux `script` is unavailable:

```bash
bun run e2e:subagents-ui
```
