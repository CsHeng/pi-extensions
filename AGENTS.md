# AGENTS.md

## Project

This repository is the authored source for small local Pi extensions. Extensions may change the host loop's active tools, prompt context, editor completion behavior, provider request payload, or execute bounded session-owned delegation; the host coding agent remains the sole lifecycle engine.

The package exposes thirteen maintained extensions: `multi-skill-mentions` as an explicit prompt expansion mechanism, `fast-gpt` as a branch-local request profile, `agents` as a bounded session-owned asynchronous managed-delegation executor, `agents-ui` as a default-loaded TUI-only read-only observer, `status-footer` as a TUI-only compact status footer, `work-timing` as TUI-only timing feedback, `tasklist` as a branch-local task list and focus aid, `job-notifications` as the sole main-model wake owner for workflow, retained shell, and subagents, `tasks-ui` as the TUI-only read-only Tasks view, `bash-jobs-ui` as the TUI-only read-only Jobs view, `agent-bark` as a main-agent-only adapter to the optional user-owned notification hook, `async-bash` as the TUI/RPC retained bash execution path, and `cache-keepalive` as the idle prompt-cache refresh while Pi's own idle warming is unreliable. Keep each extension's behavior, state, tests, and removal semantics independent.

## Layout

- `extensions/multi-skill-mentions/`: TUI completion and input expansion for loaded skills
- `extensions/fast-gpt/`: branch-local OpenAI Responses service-tier request profile
- `extensions/agents/`: fixed roles, routes, shared session capacity, managed native/Git-worktree continuity, explicit candidates, bounded observations, and the managed observer-event publisher
- `extensions/agents-ui/`: default-loaded TUI-only read-only observer. Bare `/agents-ui` toggles the above-editor section; header clicks and expand/collapse commands fold its inline rows independently from Tasks and Jobs. `/agents-ui list` and `Ctrl+Alt+F` remain separate overlay actions. Valid session agent state shows the section unless manually hidden. Completion entries stay off.
- `extensions/status-footer/`: TUI one-line footer with model/thinking, optional fast-gpt lightning, original workdir, session UUID, usage stats, context fill, and MCP counts
- `extensions/tasklist/`: Pi-owned task tracking, explicit task states, native boundary-context messages, schema-v6 snapshots with in-memory v5 normalization; independent of a Skills collection. It publishes task facts and the read-only Tasks snapshot. Job Notifications schedules model wakes; `tasks-ui` renders the widget.
- `extensions/job-notifications/`: Sole owner of main-model completion delivery for retained shell and subagents. Task-list-only continuation is disabled. Producers publish facts; process execution, child admission, and task edits remain with their respective owners.
- `extensions/tasks-ui/`: TUI-only read-only Tasks view. `/tasks-ui` is the canonical command; `/workflow-ui` is a compatibility alias. Task validation and mutation remain with Tasklist.
- `extensions/bash-jobs-ui/`: TUI-only read-only Jobs view of parent retained bash. Execution control remains with Async Bash.
- `extensions/work-timing/`: request-lane working row, per-request `work-timing-request` timing entries and interaction-lane TUI completion entries
- `extensions/shared/usage-metrics.ts`: the lane metric algorithms shared by `status-footer` and `work-timing`: timing-entry contract, per-request facts, Pi's re-bill scan, aggregation and the one metric formatter
- `extensions/agent-bark.ts`: main-agent notification adapter; it notifies once per external interaction at the shared interaction boundary (success, failure or unverifiable state) and keeps child-marker exclusion, while shared hook configuration and delivery remain user-owned
- `extensions/async-bash/`: TUI/RPC retained bash execution, bounded output, finite deadline, and inspect/wait/renew/cancel separate from that execution
- `extensions/cache-keepalive/`: idle replay of the last provider payload with a one-token response, active only while Pi's `cacheWarming` is `"streaming"`
- `config/csheng-agents.json`: packaged role routes, semantic-profile mappings, and concurrency defaults
- `.agents/skills/evaluate-subagent-runs/`: maintainer-only read-only evaluator, excluded from the npm package
- `.agents/skills/evaluate-session-cost/`: maintainer-only read-only session cost and prompt-cache evaluator, excluded from the npm package
- `tests/`: deterministic, fake-Pi, subprocess, filesystem, evaluator, and disposable-Git tests
- `scripts/`: redacted temporary-load, installed-package, and explicitly gated live E2E probes, plus the local package snapshot publisher
- `mise.toml`: `publish-local-package` task for the local Pi package snapshot
- `docs/architecture/`: stable product and maintenance truth
- `$AGENT_ARCHITECTURE_DIR/docs/`: shared boundaries, new designs/plans (including single-product changes), retained evaluation results and integration observations; runtime inputs come from the product
- `mise.toml`: source roots `AGENT_ARCHITECTURE_DIR`, `AGENT_SKILLS_DIR`, `PI_EXTENSIONS_DIR` plus `TMPDIR`; consumers use these resolved values to locate the source roots. Retained runtime and temporary artifacts belong under `$TMPDIR/extensions/`.
- Use the project environment and supported entrypoints described in `README.md#project-environment`; `mise.toml` owns ordinary development context; the product runs independently of personal global configuration. Re-establish target context when crossing projects and preserve caller-owned run isolation; keep environment values owned by `mise.toml`.
- Product protocols and independent check/install behavior remain here; runtime operates independently of the architecture checkout

## Local Package Snapshot

This checkout is authored source. Daily Pi must load a copied local Pi package; this working tree is authored source and `~/.pi/agent/extensions/` is loose-extension auto-discovery.

- Pi `packages` local paths load the directory in place. Pointing user settings at this checkout applies dirty edits on every new process or reload.
- `~/.pi/agent/extensions/` is auto-discovery for loose `*.ts` files and `*/index.ts` trees. The local package snapshot has its own install location. `rsync --delete` there would remove unrelated files, and Agents resolves packaged routes as `../../config/csheng-agents.json` from the extension file, so an extensions-only dump breaks the package baseline.
- Publish with `mise run publish-local-package`. The task runs `scripts/publish-local-package.sh` and rsyncs `package.json`, `config/`, and `extensions/` into `${PI_CODING_AGENT_DIR:-$HOME/.pi/agent}/packages/csheng-pi-extensions`.
- The publisher is bash plus a mise task because the copy is short linear rsync orchestration, this repository already owns bash probes, and mise is the local task runner. The publisher leaves `settings.json`, the user route overlay, provider/model settings, and `~/.pi/agent/extensions/` unchanged; npm publication requires a separate action.
- One-time switch: `pi remove` this checkout path from user packages, then `pi install` the snapshot directory. Later publishes only refresh the snapshot; restart Pi to load it. Refresh this local-path package with `mise run publish-local-package`; `pi update --extensions` leaves local-path packages unchanged.
- Temporary-load probes keep binding to this checkout. Installed-host probes use a disposable settings file that also points at this checkout; snapshot publication remains a separate action. Live `--installed` E2E uses the real globally installed package.

## Boundaries

- Pi's public extension API, active tool set, model context and registry, project trust, session events, and startup flags are runtime inputs.
- The host Pi loop remains authoritative for parent model turns, tool execution, persistence, user interaction, and final responses.
- Async Bash may enhance builtin `bash` only in TUI/RPC when no other extension has registered that name. Pi's public Bash operations own shell selection, launch and process-tree teardown; the wrapper owns one execution identity, bounded output, renewable finite deadlines and separate inspect/wait/renew/cancel operations. Apply cwd, environment and configured prefix once. Observation release leaves execution running; execution cancellation uses the native abort path. Print/JSON and managed child tools keep native draining Bash. Respect another shell owner and report an unknown exit as unknown, never as 0. Publish unreturned terminals as facts; Job Notifications delivers them once. Wake delivery applies to claimed TUI/RPC owners; Print/JSON and an unclaimed owner remain quiet. Reject malformed start/control combinations before execution. See [Async Bash](docs/architecture/async-bash.md).
- Cache Keepalive may send one-token replays of the last real Anthropic payload while a TUI/RPC session is idle, on Pi 1.5.0's warmer schedule and economics, and only while Pi's effective `cacheWarming` is `"streaming"`; `"idle"` or `"off"` makes it stand down. Real requests, context, settings and retention remain unchanged, and each refresh is one context-free `csheng-cache-keepalive` entry with a single attempt. It is a workaround with an exit tracked as architecture OQ-3. See [Cache Keepalive](docs/architecture/cache-keepalive.md).
- The fast-gpt extension may toggle branch-local official OpenAI and OpenAI-Codex Responses requests between top-level `service_tier: priority` and explicit `default`. Until the first `/fast-gpt` command, and for unsupported provider/API/model correlations, requests remain unchanged. Its keyed TUI status is a warning-colored ⚡ when priority is requested on a supported model. Pi and the provider remain authoritative for usage and cost; model aliases, provider overrides, pricing parsing, live calls, and workflows remain outside the extension's ownership.
- The status-footer extension may replace the TUI footer with a compact status that renders as one line on wide terminals and wraps field by field when the single line exceeds the terminal width — each field flows onto the next row only when it exceeds the remaining whitespace, adding rows and preserving fields: model and thinking, an optional warning-colored ⚡ after thinking when Pi's keyed `fast-gpt` status is present, optional `(provider sub)` when the active model is on a subscription, the session's original workdir with the Pi-provided git branch, the full session UUID, the session lane of [Usage metrics](docs/architecture/usage-metrics.md) — ↑ input, ↓ output, R cache-read, optional W cache-write, prompt-token-weighted session CH, cost excluding Pi cache-warming and cache-keepalive usage, and `RB` cache re-bill count, tokens and amount mirroring Pi's `/session` Cache Re-billed metric (Pi keeps that scan internal, so the shared module keeps a tested copy), then `✻ TTFT tok/s` joined read-only from `work-timing-request` entries and included field by field when those entries exist — current context fill, and `MCP enabled/all` from the mcp-adapter status bus. It must keep the UUID visible when width is tight even after wrapping, truncating a row only when a lone segment exceeds the width, omit generic extension-status chrome, remain inactive in RPC, JSON, and print modes, and keep session metadata unpersisted. Its metric fields are a pure function of persisted session entries and remain stable while a request is in flight. It reads the branch and keyed statuses from Pi's footer data provider without importing `fast-gpt`, spawning Git, or resolving worktree layout; Git state or chrome, working-message timing, provider billing truth, and the request-profile selection remain with their respective owners.

It also appends one context-free `work-timing-request` entry per main-session request from its `message_end` handler, before Pi persists the assistant message. The working row is the request lane and the completion entry the interaction lane of [Usage metrics](docs/architecture/usage-metrics.md); preserve the lane, cadence and request-timing contracts there and in [Work-timing metrics](docs/architecture/work-timing.md). Keep one working-line formatter/writer, TUI-only activation and interval cleanup. Keep other extensions' settings and Pi UI methods unchanged when claiming the row; co-loaded CC working-message configuration is user-owned. ## Working Rules

- Keep each extension small and independently reversible.
- Extensions share algorithms; each extension owns its state machine. When several extensions need the same judgment, such as when an external interaction ends or whether its owned execution is quiet, implement it once under `extensions/shared/` and let each extension run its own instance from its own host events. Shared modules hold algorithms and utilities; each extension owns its lifecycle. One-way read-only observation of another component's published state and optional state notifications are allowed; each extension retains exclusive ownership of its state and independent transitions. Each extension keeps its documented behavior, or a stated degradation, when any other extension is disabled or removed.
- Lead model-facing tool descriptions, context and reminders with the useful next action and the evidence that informs it. Keep negative guidance secondary and tied to concrete authority, safety or ambiguity boundaries; prefer a coherent decision path over accumulated prohibitions. Task completion needs evidence-based judgment; the tool accepts updates with no structured receipt.
- Persist only the minimum state needed to restore host behavior. Scheduling and active control remain session-owned and memory-only; an asynchronous submission remains session-owned. Managed native/source, replay, and candidate state persists only for explicit same-task actions. Historical one-shot workspaces were temporary diagnostic resources; current runtime tools follow the managed protocol. Private JSONL remains evidence; the parent owns orchestration and semantic continuation. The provenance manifest stores only the current opaque extension and configuration pair.
- Preserve ordinary Pi behavior outside each selected profile or explicit tool call and when an extension is disabled.
- Treat prompt-cache stability as a user quota/cost boundary. Under unchanged model, prompt and tool settings, ordinary turns should retain the previous complete provider input as an unchanged prefix. Keep live timing/progress in UI or explicit tool receipts; append necessary model-facing state once at a real boundary and keep the provider-input prefix stable across requests. Preserve recovery, current-state visibility and wake ownership while doing so. Legitimate compaction, explicit context edits and changed instructions remain valid context boundaries.
- For changes to context/system prompts, tool declarations or request payloads, choose affected prefix/continuity regressions and compare consecutive provider inputs with tracking or background children active where relevant. Evaluate cache/quota impact against the complete provider-input prefix, including when a suffix diff is small. Backend cache hits require backend evidence, and each route's behavior requires its own evidence even when another model shows healthy reuse. Keep diagnostic evidence redacted; existing authorized usage records are preferable to a new paid probe. Choose broad session scans, paid tests and route changes only when independently justified and authorized.
- Bound child prompts, capability files, observer snapshots, process output, diagnostic storage and individual workflow operations against their actual resource risks; workflow task history follows its documented persistence rules. Clean temporary resources on success, failure, timeout, abort, and session shutdown while retaining launched-child diagnostic sessions under their explicit retention policy.
- Keep probe and evaluator output redacted. Never print raw user settings, route files, model selectors, prompts, task IDs, credentials, environment values, session paths, or external file content.
- Treat package and user route files as read-only persistent defaults. Keep both files unchanged, including their existence, for each dispatch; explicit task route failure is typed and has no fallback or retry.
- Do not add dynamic roles, background missions, durable orchestration ledgers, hidden model fallback, automatic retry, or a Skill-specific runtime contract without a separately approved design. Explicit read-only intent, scoped access, supported host capability and real resource ownership set the tool boundary; purpose labels and child identity leave that boundary unchanged. Trusted shell execution retains host privileges; an OS sandbox would require separate isolation. The workflow extension's branch-local session snapshots are the approved ledger exception: they carry no scheduler, background execution, or automatic recovery.
- Do not commit, push, npm-publish, deploy, create a remote, install packages globally, create a user route file, or change provider/model settings without explicit authority. The local snapshot publisher is `mise run publish-local-package` and still requires that explicit authority; it must not rewrite Pi settings.

## Validation

The current managed runtime integrates `git-workspace.ts` and `session-supervisor.ts`. Stable contracts live in `docs/architecture/agent-execution.md`; dated implementation and verification records are routed through the shared coordination index. Offline synthetic host/native-child validation establishes offline behavior; live-provider effectiveness and deployment require their own evidence. Job Notifications observes published execution facts and delivers pending terminal results; task state alone never starts a model turn. Tasklist remains passive; the main agent judges task completion from evidence and owns subagent acceptance.

Use Bun 1.4.2, declared in `packageManager`, for dependency installation, TypeScript checking, tests, repository-owned e2e/probe scripts, and maintainer evaluators. Install from the tracked `bun.lock` with lifecycle scripts disabled by `bunfig.toml` and the explicit command below. The deterministic test glob excludes deliberate e2e entrypoints and uses a 120-second default per-test timeout. Keep actual installed `pi` invocations, its runtime, Pi-owned `npm:` sources and `~/.pi/agent/npm/` paths unchanged; use Bun for the repository entrypoints above. Preserve filesystem-order path regression coverage with independent fixture targets as the source of expected identities; keep expected identities independent of raw-path `realpath`.

Choose verification from the changed behavior. Workers use relevant unit tests, compilation or a narrow reproduction for local feedback, and return actual results and uncovered behavior. The main task owns integration, conflict resolution, E2E and full-suite selection, and final acceptance; it may delegate a specific check while retaining verification ownership. Reuse still-applicable worker evidence. Choose inspection and applicable structural checks for documentation or prompt-only changes when those provide proportionate evidence.

Use the existing dependency environment; install from the lockfile only when dependencies need preparation. Choose verification from these available entrypoints according to the change:

bun test ./tests/<affected-suite>.test.ts
bun run check
bash scripts/run-temporary-agents-probe.sh

bash scripts/run-installed-tasklist-probe.sh
